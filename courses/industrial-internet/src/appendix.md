## 1 论述题的四种组织方式

### 1.1 并列式：分点列举

<strong>适用</strong>：五类威胁、四大区别、三个应用方向、六个特征。

<strong>模板</strong>

```
总起（一句定义/总纲）
├─ 要点①：术语 + 一句解释 + 一个例子
├─ 要点②：……
├─ 要点③：……
└─ 收尾：这些要点共同解决了什么问题（降本/增效/提质/安全）
```

<strong>例：</strong> "工业互联网面临哪些安全威胁？"→ 总起"安全威胁可分为设备、控制、网络、应用、数据五类"
→ 五段各"变了什么 + 风险是什么" → 收尾"五类威胁构成一条攻击链，因此必须纵深防御"。

### 1.2 演进式：按阶段推进

<strong>适用</strong>：体系架构 1.0→2.0、数字化→网络化→智能化、被动→主动标识载体。

<strong>模板</strong>

```
起点（是什么、解决什么问题）
 ↓ 遇到什么瓶颈
中间态（做了什么改进、代价是什么）
 ↓ 又遇到什么瓶颈
终态（现在的形态、为什么更优）
升华：这条演进线背后的规律（如"从单点优化到全局智能"）
```

<strong>例：</strong> 架构演进 → 1.0（网络/数据/安全，三闭环，偏"数据"）→ 瓶颈：三者功能重叠 → 2.0
（网络/平台/安全，三板块）→ 升华："演进不是推翻，而是<strong>职责重新划分</strong>"（【课件 C3·P9】）。

### 1.3 对比式：逐维度对照

<strong>适用</strong>：工业互联网 vs 互联网/物联网/智能制造、IT vs OT、现场总线 vs 工业以太网、
PLC vs DCS vs SCADA、CPS vs 数字孪生。

<strong>模板</strong>

```
一句定性（两者是不是同一层次的东西）
├─ 维度①：A 是……，B 是……
├─ 维度②：……
├─ 维度③：……
└─ 关系收尾：谁包含谁 / 谁是谁的基础 / 谁是谁的目标
```

<strong>例：</strong> 工业互联网与智能制造 → 定性"两者不在同一层次：一个是基础设施与模式，一个是目标"→
三四个维度对比 → 收尾"前者是依托基础，后者是最终目标"。

### 1.4 因果链式：问题—原因—对策—效果

<strong>适用</strong>：为什么需要标识解析、为什么物理隔离不等于安全、为什么平台层是核心、
数字孪生为什么需要实时数据。

<strong>模板</strong>

```
现象（问题/痛点，最好列 3 条）
 ↓
原因（为什么会这样）
 ↓
对策（用什么技术/机制解决）
 ↓
效果（解决了之后得到什么）
```

<strong>例：</strong> "为什么要推标识解析"→ 五个痛点（国家布局缺失、国际数据安全受威胁、企业间互通难、
企业内交流难、工厂内标识复杂，【课件 C4·P18】）→ 原因（各自为政、无统一编码）→ 对策（编码 +
解析 + 分级节点）→ 效果（跨企业跨行业跨地域的数据互通与精准协同）。

### 1.5 举例式：按三层拆解一个场景

<strong>适用</strong>：要求结合具体企业或场景作答。

<strong>模板</strong>

```
场景一句（谁、造什么、什么痛点）
├─ 感知层：采什么、用什么传感器/识别技术
├─ 网络层：怎么传、用什么协议、如何保证实时与可靠
├─ 应用层：怎么决策、用什么系统（MES/SPC/数字孪生）
└─ 价值：一个数字（降本 X%、提效 Y%）
```

> 这个模板就是<strong>讲座里"三层架构"的用法</strong>（见 §4），也是"感知—传输—应用"这条主线的落地版。

## 3 四层框架图怎么画（考场 8 分钟版）

这道题（或"请画出工业互联网体系架构图"）几乎每年都可能出现。<strong>画法只有一条主线：
"四层横带 + 两条主干 + 五个协议 + 五个安全"</strong>。

### 3.1 版面（A4 横向，铅笔先打四层）

| 层 | 写什么（每层 4–6 个框即可） |
| --- | --- |
| <strong>SaaS 层 / 应用服务</strong> | MES（工单·排产·派工）、WMS（库位·出入库）、质量追溯（一物一码）、预测性维护（温振/电流趋势）、能耗管理（单件能耗·碳排）、可视化与远程运维 |
| <strong>PaaS 层 / 平台服务</strong> | MQTT Broker（设备主题·QoS1）、OPC UA Server（信息模型·地址空间）、时序数据库（秒级历史）、设备模型/数字孪生（3D 状态映射）、视觉模型训练（标注·迭代） |
| <strong>IaaS 层 / 基础设施</strong> | 服务器/虚拟化（算力池）、分布式存储（工艺文件·图像）、核心交换机/无线 AP（工业以太网·WiFi）、备份与容灾（本地+异地） |
| <strong>边缘层 / 设备与边缘</strong> | 上排边缘节点：工业网关（协议解析·OPC UA·边缘预处理）、视觉边缘服务器（GigE·缺陷推理）、工控机（MES/Ezcad 客户端）；下排现场设备：数控机床、三坐标测量仪、协作机械臂、激光打标机、工业相机+光源、AGV、PLC（S7-1500） |

### 3.2 两条主干（先画这两条，其他都对着它画）

- <strong>数据上行主干</strong>（左侧，实线，箭头朝上）：从"现场总线"起，一路向上穿过边缘层、IaaS、PaaS，
 箭头指到 SaaS 层——表示<strong>数据自下而上流动</strong>；
- <strong>控制下行主干</strong>（右侧，虚线，箭头朝下）：从 SaaS 顶端向下，到 PLC 处拐入——表示
 <strong>决策自上而下执行</strong>。

> 这两条线就是全课程的"一句话"：<strong>数据自下而上流动，决策自上而下执行</strong>（【讲座 第 9 页】）。

### 3.3 五个协议与五个安全（钉在线段旁边，不要另起一段）

| 标记 | 内容 | 钉在哪 |
| --- | --- | --- |
| ① | <strong>OPC UA + 证书</strong> | 数控机床 → 工业网关 的竖线旁 |
| ② | <strong>PROFINET</strong> | 协作机械臂 的虚线旁（向下箭头） |
| ③ | <strong>Modbus TCP</strong> | 三坐标测量仪 → 网关 的竖线旁 |
| ④ | <strong>MQTT over TLS（8883）</strong> | 数据主干的 PaaS 下方 |
| ⑤ | <strong>GigE Vision</strong> | 工业相机 → 视觉边缘服务器 的竖线旁 |
| S1 | <strong>工业防火墙 + 协议白名单 DPI、IT/OT 边界隔离</strong> | IaaS 与边缘层之间的缝，画一条贯穿全宽的斜线带 |
| S2 | <strong>OPC UA 证书双向认证</strong> | 跟 ① 一起写 |
| S3 | <strong>MQTT TLS 双向证书</strong> | 跟 ④ 一起写 |
| S4 | <strong>零信任 IAM + RBAC + 操作审计</strong> | SaaS 与 PaaS 之间的缝 |
| S5 | <strong>安全围栏：光幕 + 急停 + 激光联锁</strong> | 用点划线框住协作机械臂/打标机/相机三个框 |

## 4 讲座要点：智能制造与工业物联网（百度飞桨 / 陈科苑，51 页）

这节课是<strong>企业实践课</strong>（课件 51 页），内容为一家企业及其产线的完整案例。但它的框架极其好用，因为它把前三章的概念<strong>全部落到了一个真实工厂</strong>上。

> <strong>页码说明</strong>：本节的"第 N 页"按 <strong>PDF 页序</strong>（共 51 页）标注；该课件前几页的角标
> （右下角 "x / 56"）与 PDF 页序差 2 页，引用时以 PDF 页序为准。

### 4.1 一句话框架

> 【讲座 第 9 页】<strong>IIoT 三层架构 = 感知层（如何采集与识别）+ 网络层（如何安全可靠传输）+
> 应用层（如何处理与决策）</strong>；主线是"<strong>数据自下而上流动，决策自上而下执行</strong>"。

### 4.2 传统制造 vs 智能制造（六维对照，答"为什么要转型"时用）

> 【讲座 第 6 页】

| 维度 | 传统制造 | 智能制造 |
| --- | --- | --- |
| 生产驱动 | 经验驱动，出问题再补救 | 数据驱动，趋势预测、提前干预 |
| 设备状态 | "黑箱"，坏了才知道 | 实时监控，异常自动预警推送 |
| 质量控制 | 抽检 + 纸质记录 | 在线检测 + SPC + 全程数据追溯 |
| 信息流转 | 纸单/Excel，信息孤岛 | 系统互联互通，数据自动流动 |
| 决策方式 | 月底开会看报表，滞后数周 | 实时看板 + AI 解读，当天发现当天改 |
| 能源管理 | 月底看电费单 | 分设备分时段计量，待机浪费自动识别 |

总结句（可直接引用）：<strong>智能制造 = 在制造工艺不变的前提下，给设备装"感官"、给产线装"神经"、
给工厂装"大脑"。</strong>

### 4.3 制造企业的三大痛点与 IIoT 解法（写"落地价值"时用）

> 【讲座 第 10 页】

| 痛点 | 表现 | IIoT 解法 |
| --- | --- | --- |
| <strong>设备黑箱</strong> | 状态无记录、停机原因靠回忆、OEE 说不清 | 智能三色灯 + 电流监控，状态自动上报、OEE 自动统计 |
| <strong>质量追溯难</strong> | 手抄纸质记录、追溯靠翻本子、整改无闭环 | 量具直接上云 + 一物一码，数据不经人手、异常自动派单 |
| <strong>能源浪费</strong> | 下班不断电、只有一张总电费单 | 智能电表分设备分时段计量，待机浪费自动识别 + 电费周报 |

### 4.4 一个可直接背的完整案例：岚图云峰工厂（整车四大工艺）

> 【讲座 第 26–34 页】四大工艺：<strong>冲压 → 焊装 → 涂装 → 总装</strong>（+ 检测）。

| 工艺 | 感知层 | 网络层 | 应用层 | 关键数字 |
| --- | --- | --- | --- | --- |
| <strong>冲压</strong> | 吨位仪记录每冲次载荷曲线、板料视觉对中 | 吨位/冲次经 <strong>PROFINET</strong> 实时上传，边缘网关统一 <strong>OPC UA</strong> 接入 | 载荷超差 → 模具保护毫秒级停机；<strong>SPC</strong> 预判磨损、到期强制换模 | 7 秒/件（最高 4 秒）、误差 ≤ 0.27 mm |
| <strong>焊装</strong> | 伺服焊枪毫秒级采电流/电压、激光在线测亚毫米尺寸 | 数百台机器人实时以太网协同，焊点数据按车体编号一一绑定 | 虚焊/漏焊在线判定零流出，参数漂移自动标记复检 | 400+ 台机器人、自动化率 99%、单车 4000~5000 焊点 |
| <strong>涂装</strong> | 炉温跟踪仪随车记录烘干曲线、膜厚/色差在线检测 | 防爆本安传感网、工艺配方云端下发与 MES 排产互通 | 漆膜厚度/色差 <strong>SPC</strong> 管外观一致，成型曲线一模一档可追溯 | 防腐 12 年、控尘 5 μm、3300T 注塑机、60 秒成型 |
| <strong>总装</strong> | 数字拧紧枪扭矩 + 角度双冗余采样、RFID + 视觉防错 | 拧紧数据实时上传<strong>绑定 VIN</strong>，5G 云化 AGV 做 SPS 配送 | 自研力矩管理系统，每车每螺丝管控，拧紧不良 0 流入市场 | 118 秒/台、力矩可追溯 10 年 |

> 【讲座 第 34 页】"一辆车的数据之旅"六步（<strong>这是最好的论述素材</strong>）：
> <strong>识别（VIN 与螺栓批次扫码）→ 感知（扭矩 + 角度传感器，每秒上百次采样）→ 传输
> （PROFINET 入车间环网，毫秒级上传）→ 汇聚（边缘网关汇总，OPC UA/MQTT 上行 MES 与质量云）→
> 决策（MES 判合格放行，超差自动报警复拧）→ 沉淀（扭矩数据绑定 VIN 终身归档，支撑召回追溯）</strong>。

### 4.5 讲座里几个可引用的小结论

- <strong>OEE = 时间稼动率 × 性能稼动率 × 良品率</strong>；世界级水平 ≈ <strong>85%</strong>，多数工厂仅 <strong>40%~60%</strong>
 （【讲座 第 17 页】）——说明改善空间大。
- <strong>网络层六道防线</strong>：网络冗余（环网 < 50 ms 自愈）、断点续传、QoS 保障、IT/OT 隔离、
 硬件抗扰、管理制度（【讲座 第 41 页】）。
- <strong>落地哲学</strong>：老设备不动本体，<strong>加一个模块、通电即联网</strong>；"先解决'看得见'，再谈'想得清'"
 （【讲座 第 11、15 页】）——这是"中小企业如何起步"的标准答案。
- <strong>五大挑战</strong>：哑设备改造成本高、数据质量差、网络安全（震网为鉴）、复合型人才缺、
 投入产出周期长（【讲座 第 47 页】）。
- <strong>五大趋势</strong>：5G+TSN 普及、AI 大模型进车间、数字孪生成标配、绿色制造（碳足迹计量）、
 国产工业软件崛起（【讲座 第 47 页】）。

## 5 PLC 实验与理论的对应（实验报告/论述都能用）

本课程 12 学时实验分三次：<strong>PLC 基础操作（4 学时）→ 流水线控制实验（4 学时）→ PLC 网页交互
控制实验（4 学时）</strong>（【课件 C1·P7】）。三次实验正好对应第 5 章 CPS 那一节的三层能力：

| 实验 | 内容 | 理论对应 |
| --- | --- | --- |
| <strong>PLC 基础操作</strong> | 接线、下载程序、用梯形图实现逻辑/定时/计数 | PLC 是<strong>单元级 CPS</strong>：感知（输入采样）→ 计算（程序执行）→ 控制（输出刷新）的小闭环（`ch05` §4.2） |
| <strong>流水线控制</strong> | 多工位节拍、联锁、顺序控制 | <strong>系统级 CPS</strong>：多个单元级通过工业网络协同，构成"智能生产线"（`ch05` §4.1） |
| <strong>PLC 网页交互</strong> | 通过网页读写 PLC 变量、远程监控 | <strong>SoS 级 / 平台层</strong>的雏形：设备数据上云、远程监控与指令下发（`ch05` §4.1、`ch04` §7.3 边缘计算） |

## 6 一句话定义

下面 20 句是课件定义的精简版。

1. <strong>工业互联网</strong>：新一代信息通信技术与工业经济深度融合的新型基础设施、应用模式和工业生态。
2. <strong>工业物联网</strong>：通过工业资源的网络互联、数据互通和系统互操作，实现制造资源灵活配置、
 制造过程按需执行、制造工艺合理优化、制造环境快速适应的服务驱动型新工业体系。
3. <strong>智能制造</strong>：在制造工艺不变的前提下，给设备装"感官"、给产线装"神经"、给工厂装"大脑"。
4. <strong>物联网</strong>：通过各种信息感知装置与技术实时采集物体信息，实现物与物、物与人的泛在连接，
 对物品和过程进行智能化感知、识别和管理的网络。
5. <strong>云计算</strong>：通过网络把巨大的数据处理程序分解成小程序，由多台服务器组成的系统处理并返回
 结果的一种分布式计算。
6. <strong>工业大数据</strong>：围绕典型智能制造模式，产品全生命周期各环节产生的各类数据及相关技术和
 应用的总称。
7. <strong>工业互联网平台</strong>：面向制造业数字化、网络化、智能化需求，构建基于海量数据采集、汇聚、
 分析的服务体系，支撑制造资源泛在连接、弹性供给、高效配置的工业云平台。
8. <strong>工业互联网标识</strong>：通过数字化、编码或其他形式的唯一识别符号，为工业实体赋予独特标识，
 使其在互联网环境中被唯一识别、定位和管理的标识化系统。
9. <strong>标识解析</strong>：对标识编码进行解析，实现信息查询和定位，实现跨企业、跨行业、跨地域的数据
 互通和精准协同。
10. <strong>现场总线</strong>：应用于生产现场、在现场设备之间及现场设备与控制装置之间实行双向、串行、
 多结点通信的数字通信技术。
11. <strong>工业以太网</strong>：基于标准以太网技术、专为工业环境设计并针对工业应用优化的网络通信技术。
12. <strong>TSN</strong>：一组由 IEEE 802.1 制定的以太网增强标准，用于在标准以太网上实现确定性通信。
13. <strong>边缘计算</strong>：在靠近物或数据源头的网络边缘侧，融合网络、计算、存储、应用核心能力的
 分布式开放平台，就近提供边缘智能服务。
14. <strong>CPS</strong>：构建赛博空间与物理空间之间基于数据自动流动的"状态感知、实时分析、科学决策、
 精准执行"闭环赋能体系。
15. <strong>数字孪生</strong>：物理对象的数字模型，可通过接收物理对象的数据实时演化，从而与物理对象在
 全生命周期保持一致。
16. <strong>PLC</strong>：以计算机技术为基础、专为工业环境设计、通过可编程存储器执行逻辑/顺序/定时/
 计数/算术运算并用数字或模拟 I/O 控制机械或生产过程的数字电子装置。
17. <strong>DCS</strong>：用于工业生产过程、实现分散控制与集中管理、集 4C 技术于一体的分布式自动化控制
 系统。
18. <strong>SCADA</strong>：由计算机设备、工业过程控制组件和网络组成，对生产过程进行数据采集、监测和
 控制的系统，主要用于测控点分散、分布范围广泛的场合。
19. <strong>区块链</strong>：由区块组成的链式数据结构，且是去中心化的、不可篡改的分布式账本技术。
20. <strong>固件（Firmware）</strong>：存储在硬件设备中的特殊软件，直接控制设备底层操作，充当硬件与
 高级软件（如操作系统）之间的桥梁。
