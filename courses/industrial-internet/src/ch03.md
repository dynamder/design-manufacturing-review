# 第三章 · 一条主线

蓝图挂上了墙：网络是基础、平台是核心、安全是保障——而"各自怎么建"交给了后面几章。网络归我们。基础没法一口气建完，那就先从客户眼巴巴等着的那一件事干起：第二章那个零件。三个名字，一个零件。蓝图说"标识解析"。咱真刀真枪做一次。

## 一块不会回话的贴纸

你按任何工程师的套路开场：往零件上印个号。条形码，或者二维码。盖上去、贴上去，完事。便宜、即时，零件现在有了一个标签。

在你自己厂里，它确实管用。一扫，你就知道它是 `86.10000/ac.qd.1024`。

可看看零件出厂后发生什么。客户现场在八百公里外，那边没人揣着扫码枪到处走。标签被油糊住、被剐蹭、被铁屑埋住。即便有人真扫了，你拿到的也只是一个*编号*，仅此而已。它的"出生证"在哪个数据库？哪个系统知道它的批次？编号不说。你给这个东西起了个名，却没给它一个能查的入口。

这正是"域名"和"标识"的区别。你输入 `www.baidu.com`，域名系统（DNS）把它翻译成一个 IP 地址就完事了。而解析 `86.10000/ac.qd.1024` 这种标识时，系统必须既返回地址，又调出绑定在这个身份上的业务信息——机床、批次、刀具、历史。所以它才叫**标识解析**，也所以它是两个词、不是一个词：**标识编码**加**标识解析**。编码是那五段名字——国家、厂商、设备、城市、序列号。解析是那次查询，把名字背后的含义取出来。

| | 互联网里的计算机 | 工业里的"物" |
| --- | --- | --- |
| 名字 | 域名：`www.baidu.com` | 标识：`86.10000/ac.qd.1024` |
| 解析者 | DNS | 标识解析系统 |
| 返回 | IP：`123.125.114.114` | IP + 绑定在该身份上的业务信息 |

然后是第二个决定：标识*附着*在什么上面？有两种载体。**被动标识载体**——条形码、二维码、RFID、NFC——存着一个号，却不能自己开口；它们等着扫码枪来读。**主动标识载体**——UICC 卡、通信模组、MCU、终端——自带供电、网络和算力，能自己上报。客户现场那种永远没人会走过去扫码的地方，恰恰需要主动的那种——而它也最难，因为现在你得给每个标签都解决供电、连通和安全。

条形码给你弄到了一个名字，没给你弄到一个答案。这是坏掉的第一样东西。

## 谁的号，谁的地图？

于是你搭了一台解析服务器。它认识你的标识。麻烦在客户台账写的是 "X-3321"，而你的服务器从没听说过 "X-3321"——因为客户跑的是自己的服务器、用自己的号，两边碰不上。

这不是你代码里的 bug。这是整个行业卡了多年的结构性问题。自上而下看：

| 层级 | 痛点 |
| --- | --- |
| 国家 | 缺乏统一布局——各行业、各地区各建各的孤岛 |
| 国际 | 根节点在境外——数据主权不在自己手里 |
| 企业之间 | 协作企业的数据对不齐 |
| 单个企业内部 | ERP、SCADA、PLC、历史数据库各守各的世界 |
| 车间现场 | 零件、在制品、产品的标识各用各的编码方案 |

上面两行，一家工厂自己修不了。所以解析系统被建成一棵共享的分层树，就像 DNS 有一个全球根那样。标识解析节点分五级：**国际根节点 → 国家顶级节点 → 二级节点**（按行业或区域）**→ 企业节点 → 公共递归节点**。一次请求像 DNS 查询一样在这棵树里上上下下——只是到最后，它交回的不只是一个地址，而是绑定在这个"物"上的记录。（别把这五个*层级*跟解析架构的四个*层*弄混——编码 → 解析 → 数据 → 应用：五级说的是*谁来转发查询*，四层说的是*系统由什么构成*。）

三句话统领整个建设：**节点是基础、应用是目的、技术是保障**。先把节点铺好，让应用去拉动需求，让技术去兜底。值得认识的根体系是 **Handle**，其精神是*平等、协商、共同管理*——没有单一的主人（GHR 是全球根注册，ARS 是辅助根，LHS 是下级授权节点）。

而这一切的回报，被压缩成六句承诺，即"六个一码"：**一码一物**、**一码上云**、**一码全览**、**一码协同**、**一码分权**、**一码万能**。从单个零件一直到服务生态，一个身份贯穿始终。

零件在纸面上可追溯了。但一个身份，只有在承载它的东西能*开口说话*时才值钱。还记得第一章那五个问题——快、丢、准、活着、说得上话吗？我们用现场总线买下了快、丢、准。"活着"和"说得上话"还一直记在账上。该修管道了。

## 两座工厂，两个世界

你的网络得覆盖两个几乎毫无共同点的地方。厂内，每一根线都是你的，你可以要求毫秒级的确定性。厂外，是 800 个客户现场、你自己的分支机构、供应商和云——没一个你说了算。一套设计伺候不了两边，所以你画两套。

这就是网络连接框架的第一刀。它有三件活——**网络互联**（连）、**数据互通**（懂）、**标识解析**（找）——再水平切成**工厂内网**和**工厂外网**。

厂内，内网是"两层三级"。两层是 **IT**（信息技术——办公室、企业）和 **OT**（运营技术——车间、机器）。三级是**企业级、车间级、现场级**：IT 管企业级（ERP、MES、SCM、CRM、数据中心）；OT 管车间级（工业以太网、HMI、SCADA）和现场级（PLC、DCS、现场总线、机器本身）。换个切法——按*业务*而不是按楼层——同一张内网又分四张网：**生产网**、**办公网**、**安防网**和**企业数据中心**。

厂外，外网是"三个专线 + 一个连接"：**上网专线**（OTN / MPLS VPN）把工厂接到互联网；**互联专线**（SD-WAN）接到分支机构和供应商；**上云专线**（云 VPN）接到工业云；而孤零零的那个**连接**（上网连接，LTE / 5G / NB-IoT）够到已经卖给客户的机器。前三个用"专线"，因为两端都是组织、要带宽要隔离；最后一个用"连接"，因为那一头是散落在上千个车间里的产品，只能走公共无线。

现在每个盒子都有了管道。但"连上了"不等于"听得懂"。一上电，你就听到真正的问题：PLC 说 Profinet，老传感器在 RS-485 上嘀咕 Modbus，AGV 在无线上嚷嚷，没人翻译。

## 一座巴别塔

这就是第一章"说得上话"问题的具体化。车间从来不是按"一种语言"设计的——它一代设备长出一种协议。整个家族先按介质分，再分成三类：**现场总线**（最老的有线方言）、**工业以太网**（为工厂加硬的以太网）、**工业无线网络**。

- 现场总线——你会碰到的八个名字：ProfiBus、ModBus、DeviceNET、CANOpen、CC-Link、AS-I、InterBus、ControlNet。Modbus 最要紧，因为它是多年里大家的"共同语言"。
- 工业以太网——四个：**Profinet、EtherNet/IP、EtherCAT、ModBus TCP**。和办公室一样的以太网帧，为实时做了调校。
- 无线——又是八个：WLAN、Bluetooth/BLE、WIA-PA/WIA-FA、LoRa、WirelessHART、ZigBee、ISA100.11a、6LoWPAN。

这些你一条都不拆——机器都是花了钱的。你翻译。三条路（异构协议互通）：盒子上的**网关与中间件**，中间的**协议适配器与转换软件**，数据层的**协议数据格式转换**。让它奏效的窍门：网关朝*南*听设备说什么方言，中间转格式，朝*北*对上游所有系统讲一种统一模型——通常是 **OPC UA** 或 **MQTT**。南边，多种方言；北边，一种。

现在一切都说得上话了。但"说得上话"不等于"按时说得上话"。表上还有三根线头吊着。

## "按时"的三件工具

第一根线头是距离。客户现场在 800 公里外，表上还承诺了远程可视和 4 小时到场响应。有线现场总线够不着，只能无线。这就是**5G**（第五代移动通信），用五个数字记住它：每平方公里百万连接、每秒千兆、一毫秒时延、99.9999% 可靠性、一微秒抖动。三项技术让它成真——高频 + 多天线、**网络切片**、**边缘计算**——它解锁五类应用：远程协同、智能生产、产品即服务、精细化无人控制、供需实时匹配。

第二根线头是确定性。即便在厂内，普通以太网也是尽力而为：包会排队、碰撞、重传，所以延迟是*不可预测*的。主轴伺服等不起路由器"想不想转发"。这就是**时间敏感网络**（TSN）：一组 IEEE 802.1 以太网扩展标准，交付**确定性通信**。把它读成四种老毛病、四味药：

| 传统以太网的问题 | TSN 的机制 | 你得到的 |
| --- | --- | --- |
| 实时性差 | 时间同步 | 按时送达 |
| 数据抖动 | 流量控制 | 数据可靠 |
| 传输冲突 | 冗余恢复 | 可用性 |
| 资源争用 | 优先级管理 | 精准性 |

把 TSN 剥到核，就是两样东西：一个**全局时钟**，一个**传输调度器**，按时刻表放行每一条流。"这个帧什么时候到"不再是赌，而是能算出来的数。

第三根线头还是距离，但这次是数据的距离。800 台机床流个不停，把每个字节都送到远方的云，慢、贵，而且不关云的事——主轴报警该*立刻*触发本地停机，而不是等它去上海打个来回。这就是**边缘计算**：一个开放、分布式平台，在*靠近*数据源头的地方融合**网络、计算、存储、应用**能力，就近提供智能。它的入口设备是**边缘计算网关**。与云的分工（边云协同）是脊髓反射之于大脑：边缘处理实时、短周期的活，把摘要往上送；云处理长周期、全车队的分析，把模型往下推。

## 收个尾

三根线头，三件工具，网络层终于立住了：**连**（互联，内网与外网）、**懂**（协议翻译成一种模型）、**找**（标识与解析）。数据现在从 800 台机床稳稳地、可信地流向云端。

而就在这里，我们撞上了那堵一直装没看见的墙。云里堆满了数据，表上的要求却一个字没少：OEE 必须*协商一致*，追溯必须 48 小时内交出机床、批次和刀具。躺在桶里的数据不是服务。总得有人把这条流，变成客户愿意签字的那个东西。那是平台的活——也是下一章。
