# 第 3 章 工业互联网体系架构

> 本章对应课件《第 3 章 工业互联网体系架构》（共 30 页）。
> 图例：加粗 = 课件原文中以红色（深红或纯红）标出的内容，句尾〔标红 C3·Py〕标注来源页。本文不用加粗表达其他强调。

工业互联网体系架构回答"工业互联网由哪些部分构成、各部分如何协作"。它经历了两代：**1.0**（2016）〔标红 C3·P5〕与 **2.0**（2019）〔标红 C3·P9〕。理解的主线只有一条——从"目标"到"能力"再到"落地"：业务视图回答"做什么"，功能架构回答"需要什么能力"，实施框架回答"怎么建"。

## 3.1 两代体系架构：1.0 与 2.0

### 3.1.1 1.0 的三大核心：网络、数据、安全

体系架构 1.0 提出，**网络、数据、安全**是工业互联网体系构建的三大核心〔标红 C3·P5〕：

- **网络**：工业系统互联和工业数据传输交换的支撑基础；
- **数据**：工业智能化的核心驱动；
- **安全**：网络与数据在工业中应用的重要保障。

![图 3-1 工业互联网体系架构 1.0：网络、数据、安全三大核心（课件 C3·P5）](assets/figs/c3_arch10.jpg)

*图 3-1 工业互联网体系架构 1.0：网络、数据、安全三大核心（课件 C3·P5）*

> 注意 1.0 的核心里是"数据"，不是"平台"——这是它与 2.0 的分水岭，见 §3.1.3。

在三大核心之上，1.0 提出三个优化闭环〔标红 C3·P6〕，分别面向机器、生产与商业：

| 闭环 | 数据基础 | 手段 | 结果 |
| --- | --- | --- | --- |
| **机器设备运行优化** | 机器操作数据、生产环境数据的实时感知 | 边缘计算 | 设备的动态优化调整，构建智能机器与柔性生产线 |
| **生产运营优化** | 信息系统、制造执行系统（MES）、控制系统数据的集成处理 | 大数据建模分析 | 生产运营的动态优化，形成智能生产模式 |
| **企业协同、用户交互与产品服务优化** | 供应链、用户需求、产品服务数据的综合集成与分析 | 综合集成与分析 | 资源组织与商业活动的创新，形成网络化协同、个性化定制、服务化延伸等新模式 |

三个闭环的边界按"一台设备 → 一条产线 → 一家企业"逐层放大：设备闭环让单台机器"别犯病"，运营闭环让整条产线"别停摆"，商业闭环让生意"别掉链子"。

### 3.1.2 从 1.0 到 2.0 的演进

演进分三个阶段〔标红 C3·P8〕：

数字化（**单点优化**）→ 网络化（**全面互联**）→ 智能化（**全局智能**）

三个阶段是能力递进，而非替换：后者以前者为基础。

与此同时，课件点明了三大体系的定位〔标红 C3·P8〕：网络体系是**基础**、平台体系是**核心**、安全体系是**保障**。这句是全书反复出现的一句话，第 1 章绪论〔C1·P21〕、第 5 章平台〔C5·P3〕都沿用同一表述。

### 3.1.3 2.0 的三大体系与三大板块

2.0 充分继承了 1.0 的核心思想〔标红 C3·P9〕，但做了一处关键调整：以**平台**替代**数据**，形成**网络、平台、安全**三大体系〔标红 C3·P9〕。

> 为什么换？1.0 里"网络、数据、安全"在"数据"这一功能上重叠——网络要传输数据、数据本身是核心、安全要保护数据，三者都围着"数据"转。2.0 于是单独设立"平台"来承载数据的集成、管理与建模分析〔标红 C3·P9〕，让三者各司其职：网络管"通"、平台管"算"、安全管"保"。功能内涵与 1.0 基本一致，只是职责划分更清晰。

体系架构 2.0 由**业务视图、功能架构、实施框架**三大板块构成〔标红 C3·P10〕，遵循"以商业目标和业务需求为牵引，进而明确系统功能定义与实施部署方式"的设计思路。

![图 3-2 工业互联网体系架构 2.0 的三大板块：业务视图、功能架构、实施框架（课件 C3·P10）](assets/figs/c3_arch20.jpg)

*图 3-2 工业互联网体系架构 2.0 的三大板块（课件 C3·P10）*

| 板块 | 明确的内容 |
| --- | --- |
| 业务视图 | 企业实现数字化转型的目标、方向、业务场景及相应的数字化能力 |
| 功能架构 | 支撑业务所需的核心功能、基本原理和关键要素 |
| 实施框架 | 各项功能落地实施的层级结构、软硬件系统和部署方式 |

## 3.2 业务视图：四个层次

业务视图把工业互联网的参与方分成**产业层、商业层、应用层、能力层**四个层次〔标红 C3·P13〕：

| 层次 | 视角 | 关注 |
| --- | --- | --- |
| **产业层** | 宏观 | 产业整体的数字化转型 |
| **商业层** | 微观 | 企业数字化转型（业务与商业模式） |
| **应用层** | 微观 | 企业数字化转型（具体应用场景） |
| **能力层** | 微观 | 企业数字化转型（所需的数字化能力） |

四个层次里只有**产业层**是宏观视角，其余三层都是企业微观视角〔标红 C3·P13〕。

> 一个容易混的点：这里的"应用层"是业务视角的应用场景，与功能架构里平台体系的"应用层"（技术分层，见 §3.3.3）不是一回事，只是恰好同名。

## 3.3 功能架构：核心功能原理与三大功能视图

功能架构先给一个总纲（核心功能原理），再展开成网络、平台、安全三张功能视图。

### 3.3.1 核心功能原理

工业互联网的**核心功能原理**，是基于数据驱动的**物理系统**与**数字空间**全面互联与深度协同，以及在此过程中的智能分析与决策优化〔标红 C3·P15〕。

拆成三步理解：先让物理系统与数字空间全面互联，再深度协同，最后以智能分析支撑决策优化。

### 3.3.2 网络功能视图：网络互联、数据互通、标识解析

网络体系由**网络互联、数据互通、标识解析**三部分组成〔标红 C3·P16〕：

- **网络互联**——把要素"连起来"，实现数据传输；
- **数据互通**——让要素"听得懂"彼此，实现相互理解；
- **标识解析**——给要素"上户口"，实现标记、管理和定位。

![图 3-3 网络功能视图：网络互联、数据互通、标识解析（课件 C3·P16）](assets/figs/c3_net_view.jpg)

*图 3-3 网络功能视图（课件 C3·P16）*

三者的关系可概括为"连得上（互联）→ 听得懂（互通）→ 找得到（解析）"。

（1）**网络互联**——通过有线、无线方式，把工业互联网相关的**人、机、物、料、法、环**以及企业上下游、智能产品、用户等**全要素**连接起来，支撑端到端数据传输〔标红 C3·P17〕。

| 子功能 | 内容 | 典型技术 |
| --- | --- | --- |
| 多方式接入 | 有线接入 | 现场总线、工业以太网、工业 PON、TSN |
| | 无线接入 | 5G/4G、WiFi/WiFi6、WIA、WirelessHART、ISA100.11a |
| 网络层转发 | 工业非实时 / 实时数据转发、网络控制、网络管理 | — |
| 传输层传送 | 端口管理、端到端连接管理、安全管理 | — |

（2）**数据互通**——实现数据和信息在各要素间、各系统间的无缝传递，让异构系统在数据层面相互"理解"，实现数据互操作与信息集成〔标红 C3·P18〕。

| 层次 | 作用 | 代表协议 |
| --- | --- | --- |
| 应用层通信 | 建立、维持、关闭数据传输的安全通道，管理装备、传感器等设备节点 | OPC UA、MQTT、HTTP |
| 信息模型 | 提供完备、统一的数据对象表达、描述与操作模型 | OPC UA、MTConnect、YANG |
| 语义互操作 | 数据信息的发现、采集、查询、存储、交互，及请求/响应、发布/订阅 | OPC UA、PLCopen、AutoML |

其中提供统一信息模型的是 OPC UA / MTConnect / YANG；用于发布/订阅的轻量协议是 MQTT（属于应用层通信）。

（3）**标识解析**——提供六项功能〔标红 C3·P20〕：

| 功能 | 内容 |
| --- | --- |
| **标识数据采集** | 标识的识读与数据预处理（标识读写、数据传输） |
| **标签管理** | 载体数据信息的存储、管理与控制（标识载体形式、标识编码存储形式） |
| **标识注册** | 在系统中创建并维护对象标识的注册数据 |
| **标识解析** | 按标识编码查询目标对象的网络位置或相关信息 |
| **标识数据处理** | 采集数据的清洗、存储、检索、加工、变换与传输 |
| **标识数据建模** | 构建领域标识数据服务模型，建立数据字典、知识图谱等 |

六项功能是一条流水线：采集 → 管标签 → 注册 → 解析 → 处理 → 建模。打个比方，这像一票快递的旅程：采集是"扫件"、标签管理是"贴单"、注册是"入库"、解析是"查它现在在哪"、处理是"分拣"、建模是"摸清哪个仓库该备多少货"。

### 3.3.3 平台功能视图：边缘层、PaaS 层、应用层

按功能层级，工业互联网平台包括**边缘层、PaaS 层、应用层**三个关键功能组成部分〔标红 C3·P21〕：

- **边缘层**：海量工业数据的接入、转换、数据预处理和边缘分析应用；
- **PaaS 层**：资源管理、工业数据与模型管理、工业建模分析、工业应用创新；
- **应用层**：工业创新应用、开发者社区、应用商店、应用二次开发集成。

![图 3-4 平台功能视图：边缘层—PaaS 层—应用层（课件 C3·P21）](assets/figs/c3_platform_view.jpg)

*图 3-4 平台功能视图（课件 C3·P21）*

> 名称相近的两件事：第 3 章的"平台功能视图"是 3 层（不含 IaaS）；第 5 章的"平台功能架构"是 4 层（边缘层、IaaS 层、平台层/工业 PaaS、应用层/工业 SaaS，〔标红 C5·P13〕）。

### 3.3.4 安全功能视图：五大安全

工业互联网安全体系框架聚焦五大安全，包括**可靠性、保密性、完整性、可用性、隐私和数据保护**〔标红 C3·P23〕。

![图 3-5 安全功能视图：可靠性、保密性、完整性、可用性、隐私和数据保护（课件 C3·P23）](assets/figs/c3_safety_view.jpg)

*图 3-5 安全功能视图（课件 C3·P23）*

与信息安全经典的 CIA 三性（保密性、完整性、可用性）相比，工业互联网多出两项：**可靠性**（工业系统不能停机）和**隐私和数据保护**。这两项正是"工厂"与"互联网"安全诉求的差别所在。

### 3.3.5 功能架构总图：4 个层次 × 3 个体系

功能架构整体上是一个"4 层 × 3 体系"的矩阵：

- 4 个层次：**设备层、工厂层、企业层、产业层**〔标红 C3·P25〕；
- 3 个体系：**网络体系、平台体系、安全体系**〔标红 C3·P24〕。

## 3.4 实施框架：四大实施系统

从"能力"落到"建设"，实施框架给出四大实施系统：**网络系统、标识系统、平台系统、安全系统**〔标红 C3·P29〕。

注意这里是"**标识**系统"而非"数据系统"：到了落地层面，标识解析被单列为一个可建设的系统（对应第 4 章的标识解析体系）。

三大板块与四大系统的对应关系：

| 板块 | 回答的问题 | 内容 |
| --- | --- | --- |
| 业务视图 | 做什么 | 产业层 / 商业层 / 应用层 / 能力层 |
| 功能架构 | 需要什么能力 | 4 层（设备/工厂/企业/产业）× 3 体系（网络/平台/安全） |
| 实施框架 | 怎么建 | 4 系统（网络/标识/平台/安全） |

## 本章小结

- 1.0（2016）三核心：网络（支撑基础）、数据（核心驱动）、安全（重要保障）。
- 三大优化闭环：机器设备运行优化（边缘计算）、生产运营优化（大数据建模）、企业协同与用户交互优化（综合集成）。
- 演进三阶段：数字化（单点优化）→ 网络化（全面互联）→ 智能化（全局智能）。
- 2.0（2019）三体系：网络（基础）、平台（核心）、安全（保障）；以平台替代数据，承载数据的集成、管理与建模分析。
- 三板块：业务视图 → 功能架构 → 实施框架。
- 业务视图四层次：产业层（宏观）、商业层、应用层、能力层（微观）。
- 核心功能原理：物理系统与数字空间全面互联与深度协同，再加智能分析与决策优化。
- 网络三部分：网络互联（传输）、数据互通（理解）、标识解析（标记/管理/定位）。
- 标识解析六功能：采集、标签管理、注册、解析、处理、建模。
- 平台功能视图三层：边缘层、PaaS 层、应用层（第 5 章功能架构为四层）。
- 安全五性：可靠性、保密性、完整性、可用性、隐私和数据保护。
- 功能架构：4 层（设备/工厂/企业/产业）× 3 体系（网络/平台/安全）。
- 实施框架四系统：网络、标识、平台、安全。
