## 1 工业互联网标识（4.1）

### 1.1 从身份证到标识：三个类比

> 【课件 C4·P5】身份证号码**唯一对应每个公民**；IP 地址**唯一对应互联网中每台计算机**；
> 各类工业产品及设备也需要自己唯一的"**身份证**"进行统一管控。

> 【课件 C4·P6】**定义**：工业互联网标识是一种**标识化系统**，通过**数字化、编码或其他形式
> 的唯一识别符号**，为工业物品、设备、产品等实体赋予独特的标识符号，使其能够在互联网环境中
> 被**唯一识别、定位和管理**。

**标识与域名的对照**（【课件 C4·P6】，这张表把"标识解析"和"DNS"讲透了）：

| 对比项 | 互联网计算机标识 | 工业互联网标识 |
| --- | --- | --- |
| 名字 | 域名：`www.baidu.com` | 标识：`86.10000/ac.qd.1024` |
| 结构 | — | **国家 / 厂商 / 设备 / 城市 / 序列号** |
| 解析系统 | **域名解析系统（DNS）** | **标识解析系统** |
| 解析结果 | IP 地址：`123.125.114.114` | IP 地址：`3ffe:8080::1` **+ 标识关联的信息** |

标识编码 `86.10000/ac.qd.1024` 的五段含义：**国家、厂商、设备、城市、序列号**。

> 【课件 C4·P7】标识解析系统的作用：多个"国家、企业、类别、序列号"各自**唯一对应**一个标识，
> 通过标识解析系统实现**数据互通**与**综合管理**，最终实现工业互联网设备、产品、人员、企业
> 的**高效管控**。

### 1.2 两类标识载体

> 【课件 C4·P8–9】工业互联网标识载体分**被动标识载体**与**主动标识载体**。

| 类别 | 载体形式 | 特点 | 优点 | 不足 |
| --- | --- | --- | --- | --- |
| **被动标识载体** | **条形码、二维码、射频识别（RFID）、近场通信（NFC）** | 自身**不带电**，靠外部读写设备"读取" | 成本极低（条码/二维码近乎零成本）、技术成熟、易印刷 | 需外部设备读、**读写距离近**、条码易污损、**不能主动上报** |
| **主动标识载体** | **通用集成电路卡（UICC）、通信模组、芯片（MCU）、终端** | 自带**通信与计算能力**，可主动联网上报 | 可**主动上报**、可远程管理、可承载更多数据 | 成本高、**需要供电**、改造难度大（课件问"哪个更难"） |

"主动标识载体为什么比被动标识载体难？ "——三个理由：① **要供电**（现场取电难）；② **要联网**（协议/网络配置复杂）；③ **要安全**（密钥、证书、远程升级都要管）。而被动载体只要"印上去/贴上去"就行。课件 P9 那句"优点和不足？ 哪个更难？ "就是埋的这个点。

RFID 属于**被动标识载体**（课件 P8 明确列在被动里），尽管它"无线"。判断标准是**能不能自己主动发起通信并携带智能**，不是"有没有无线电"。

### 1.3 标识的应用流程与安全体系

> 【课件 C4·P10】应用流程：**产品生产/设备部署 → 标识分配 → 标识解析系统（标识编码生成、
> 标识入库）→ 生产管理 / 状态监控 / 数字化管理**。

> 【课件 C4·P11】标识安全体系（两大部分）：
> - **标识安全性**：加密（**加密传输、加密编码**）、**身份验证**、**访问控制**、**数据备份**、
> **网络安全**；
> - **标识隐私保护**：**数据匿名**、**隐私政策**、**标识生命周期管理**。

### 1.4 标识的作用与六个"一码"

> 【课件 C4·P12】标识的支撑作用（六个方向）：
> ① **设备定位跟踪**；② **提高生产效率**；③ **促进可识别数据对象的管理和交互**；
> ④ **标准化管理**；⑤ **提升设备互操作性**；⑥ **降低产业成本**；
> 并且**支撑工业互联网网络互联互通**、**支撑工业互联网数据共享共用**。

> 【课件 C4·P13】六个"一码"（非常好记，也常出简答）：

| 提法 | 含义 |
| --- | --- |
| **一码一物** | 一个标识码对应一个产品，扫码解析获得产品全信息 |
| **一码上云** | 一个标识码连接设备上云，实现设备生命周期全监控 |
| **一码全览** | 一个标识码查看所有环节，快速了解产品质量全追溯 |
| **一码协同** | 一个标识码实现协同到底，帮助企业数据共享全打通 |
| **一码分权** | 一个标识码实现多种识别，帮助企业不同对象全管控 |
| **一码万能** | 一个标识码实现万个功能，帮助企业提供产品全服务 |

"**物、云、览、同、权、能**"——一个字对应一个"一码"。

## 2 工业互联网标识解析（4.2）

### 2.1 定义与核心内容

> 【课件 C4·P17】**工业互联网标识解析**：将产品、零部件、生产设备、生产过程、供应链等
> **全生命周期各环节信息赋予唯一标识**，通过对**标识编码进行解析**，实现**信息查询和定位**，
> 实现**跨企业、跨行业、跨地域**的数据互通和精准协同。

> 【课件 C4·P17】核心内容两部分：**标识编码** + **标识解析**。

解析过程（【课件 C4·P17】的流程图，一段话讲清）：

> 标识解析发起方发出**标识解析请求** → **标识解析节点**把标识**寻址到目标地址** →
> 返回**标识所关联对象的地址** → 由**数据服务器**返回**标识所对应的信息对象**。

"标识解析与 DNS 的区别"——三条：① DNS 解析的是**域名→IP**，标识解析是**标识→地址 + 关联信息**；② DNS 是**全球统一**的（ICANN），标识解析是**多根并存**的（Handle/DNS/OID/GS1/DID 各自有根）；③ 标识解析还要解决**跨企业、跨行业、跨地域**的**数据互通与确权**问题，DNS 不管这些。

### 2.2 为什么要推标识解析：五个痛点

> 【课件 C4·P18】"为什么要推广标识解析体系？"——课件用一张图列了五个问题：

| 痛点 | 表现 |
| --- | --- |
| **国家内统一布局缺乏** | 各行业、各地区自建体系，互不相通 |
| **国际上数据安全受威胁** | 根节点在境外，数据主权受制于人 |
| **企业间信息互通困难** | 协作企业之间数据对不上 |
| **企业内数据交流困难** | 历史数据库、SCADA、工业 PC、PLC 各自为政 |
| **工厂内设备标识复杂** | 零部件标识、在制品标识、产品标识各不相同 |

这五条是"为什么要建国家标识解析体系"的标准答案。

**（2）Handle 根体系**

> 【课件 C4·P22】

| 缩写 | 含义 |
| --- | --- |
| **GHR** | **国际并联根节点**（Global Handle Registry） |
| **ARS** | **全球辅根节点**（全球所有 Handle 根系统 MPA 之间**平等、协商、共管**） |
| **ARS-MPA** | MPA 辅根节点（国家工业互联网节点、电子政务节点等） |
| **LHS** | **下级授权节点**（行业节点、区域节点、企业节点、N 级节点） |

解析方式（同页）：**缓存/递归解析服务节点**提供**递归解析**与**缓存解析**。

GHR = 国际并联根节点；ARS = 全球辅根节点；LHS = 下级授权节点。Handle 体系的核心理念是"**平等、协商、共管**"，不是"美国主导"。

## 4 工厂内网络（4.4）

### 4.1 "两层三级"结构

> 【课件 C4·P33】工厂内网络呈现为**两层三级**的结构：
> - **两层**：**工厂 IT 网络（信息技术网络）** 和 **工厂 OT 网络（运营技术网络）**；
> **IT 层覆盖工厂/企业级，OT 层覆盖车间级和现场级**；
> - **三级**：按工厂管理层级划分，网络分为**工厂级/企业级、车间级、现场级**。

![图 4-4 工厂内网络的两层三级：IT 网络（企业级）+ OT 网络（车间级、现场级）（课件 C4·P33）](assets/figs/c4_two_layer_three_level.jpg)

*图 4-4 工厂内网络的两层三级：IT 网络（企业级）+ OT 网络（车间级、现场级）（课件 C4·P33）*

图中各层的代表设备：

| 层级 | 所属 | 代表系统/设备 |
| --- | --- | --- |
| **工厂级/企业级** | **工厂 IT 网络** | 办公网、企业内数据中心、**SCM、MES、ERP、CRM**、网络防火墙 |
| **车间级** | **工厂 OT 网络** | 生产网、**SCADA**（数据采集与监视控制）、**HMI**（人机界面）、工业以太网/无线网络、**工业防火墙**、AOE 监测系统 |
| **现场级** | **工厂 OT 网络** | **PLC**（可编程控制器）、现场总线/工业以太网/无线网络、**DCS/FCS**（过程控制/分散控制系统）、机器 1/2/3 |

"IT 网络与 OT 网络的主要区别"（课后题 6）——四条：① **关注点**：IT 重**数据传输与业务协同**，OT 重**实时控制与生产连续性**；② **实时性**：IT 容忍秒级延迟，OT 要求毫秒级确定性；③ **协议**：IT 用 TCP/IP、HTTP，OT 用现场总线/工业以太网（Profinet、Modbus 等）；④ **安全**：IT 可随时打补丁重启，OT **不能随便停线**，所以用"工业防火墙 + 白名单"而非"杀毒软件"。（②③④中 ① 为课件 P33 图示含义，其余标【补充】。）

### 4.2 按业务分类：四张网

> 【课件 C4·P39–41】工厂内网按业务分：**生产网、办公网、安防网、企业数据中心**。

| 网 | 承载的业务 |
| --- | --- |
| **生产网** | **控制类**（产线控制、远程控制）、**采集类**（传感器采集、环境传感、视频检测与采集）、**连接类**（设备自动化程序下载、生产加工程序下载、基于无线网络的 AGV 导航、远程诊断维修指导） |

### 6.2 现场总线协议

> 【课件 C4·P51】**现场总线协议**是工业自动化中，用于**现场设备与控制系统之间**数字通信的
> **标准化通信协议**，支持**实时、可靠**的数据交换。是一种**数字化、双向、多节点**通信网络。

| 协议名 | 协议名 |
| --- | --- |
| **ProfiBus** | **ModBus** |
| **DeviceNET** | **CANOpen** |
| **CC-Link** | **AS-I** |
| **InterBus** | **ControlNet** |

> 【课件 C4·P52】Modbus 的特殊地位：为装置和设备之间的通信提供了一种**通用语言**；
> 串口通信形式包括 **RS232、RS485、RS-422**。

Modbus 的三种串口形式：**RS232 / RS485 / RS-422**。AS-I 是"执行器—传感器接口"（Actuator Sensor Interface），属现场总线；别和"ASI"混淆。

### 6.3 工业以太网协议（四个名字）

> 【课件 C4·P54】工业以太网协议是一种**基于以太网技术**的网络协议，用于工业控制系统和自动化
> 控制系统：**Profinet、Ethernet/IP、EtherCAT、ModBus TCP**。

> 【课件 C4·P55】EtherNet/IP 的细节（选择题爱考）：基于标准以太网协议（**IEEE 802.3**），
> 支持 **TCP 与 UDP** 传输协议，支持**数种网络拓扑**（星型、总线型等）。
> 以太帧结构：Ethernet Header → IP Header → TCP/UDP Header → Encapsulation Header →
> Encapsulation Data → Trailer。

"EtherNet/IP 基于哪个标准" → **IEEE 802.3**；"支持哪两种传输层协议" →**TCP 和 UDP**。

### 7.1 5G

> 【课件 C4·P62】5G 的**超大带宽、超低时延、海量覆盖**特性，与工业互联网的要求和目标高度契合，

五类应用（【课件 C4·P62】）：**远程协同管理**（多地远程协同在线研发设计）、**智能化生产**

**管控精细化无人化**（机器视觉 + 5G 提升质量管理实时性）、**供需对接实时化**（供应链与市场
供需信息对接）。

**5G 的五个关键指标**：

| 指标 | 数值 |
| --- | --- |
| **广连接** | **1 百万 / km²** |
| **大带宽** | **1 Gbit/s** |
| **低时延** | **1 ms** |
| **高可靠** | **99.9999%** |
| **微抖动** | **1 μs** |

三项使能技术：**5G 高频和多天线技术、5G 网络切片技术、
5G 边缘计算技术（AI）**。

5G 三个"1"：**1 ms、1 Gbit/s、1 百万/km²**；两个"9 的个数"：可靠性 **99.9999%**（四个 9）；抖动 **1 μs**。

### 7.2 时间敏感网络（TSN）——本章最可能出论述的技术点

**（1）TSN 要解决传统工业以太网的什么问题**

> 【课件 C4·P64】传统工业以太网有四个毛病，TSN 用四种机制逐一对应：

| 传统工业以太网的问题 | TSN 的机制 | 得到的能力 |
| --- | --- | --- |
| **实时性差** | **时间同步机制** | 传输实时性 |
| **数据抖动** | **流量控制机制** | 数据可靠性 |
| **传输碰撞** | **冗余恢复机制** | 网络可用性 |
| **资源竞争** | **优先级管理** | 传输精准性 |

![图 4-6 TSN 用时间同步、流量控制、冗余恢复、优先级管理解决传统工业以太网的四个问题（课件 C4·P64）](assets/figs/c4_tsn.jpg)

*图 4-6 TSN 用时间同步、流量控制、冗余恢复、优先级管理解决传统工业以太网的四个问题（课件 C4·P64）*

**（2）TSN 是什么**

> 【课件 C4·P64】TSN 是一种具有**低传输时延、低传输抖动和极低数据丢失率**的高质量**实时
> 传输网络**。

> 【课件 C4·P65】TSN 是一组由 **IEEE 802.1** 制定的**以太网增强标准**，用于在标准以太网上
> 实现"**确定性通信**"，确保关键数据在**严格的时间限制内**以**低延迟、低抖动、高可靠性**
> 方式传输。

**（3）TSN 的工作原理**

> 【课件 C4·P66】TSN 通过一个**全局时钟**和一个**连接各网络组件的传输调度器**，实现了网络内的
> **确定性实时通信**。

三个关键词：**时钟同步 + 实时调度 + 确定性传输**（【课件 C4·P66–68】的图就是这三个框）。

"TSN 与普通以太网的本质区别"——一句话：普通以太网是**"尽力而为"（best effort）**，冲突时排队重发，延迟不确定；TSN 通过**全局时钟 + 时间片调度**让关键流量在**确定的时刻**占用链路，做到**确定性（deterministic）**。所以 TSN 是"工业实时控制能不能跑在以太网上"的关键。

## 本章要点

1. **标识定义**：数字化/编码的唯一识别符号，使实体能被**唯一识别、定位和管理**。
2. **两类载体**：被动（条码、二维码、RFID、NFC）、主动（UICC、通信模组、MCU、终端）。
3. **标识 vs 域名**：标识 = 国家/厂商/设备/城市/序列号；解析返回 **IP + 关联信息**。
4. **六个"一码"**：一码一物、一码上云、一码全览、一码协同、一码分权、一码万能。
5. **标识解析核心内容**：**标识编码 + 标识解析**。
6. **五大痛点**：国家布局缺乏、国际数据安全受威胁、企业间互通难、企业内交流难、工厂内标识复杂。
7. **节点五级**：国际根节点（Handle/DNS/OID-GS1/DID）→ 国家顶级节点（京沪渝穗汉）→ 二级节点
 → 企业节点 → 公共递归节点；**节点是基础、应用是目的、技术是保障**。
8. **功能视图四层**：标识编码层、标识解析层、标识数据层、标识应用层。
9. **Handle 体系**：GHR（国际并联根）、ARS（全球辅根）、LHS（下级授权）。
10. **网络连接三部分**：网络互联、数据互通、标识解析。
11. **工厂内网两层三级**：IT（企业级）/OT（车间级、现场级）；按业务分生产网、办公网、安防网、
 企业数据中心。
12. **工厂外网四专线**：上网专线（OTN/MPLS VPN）、互联专线（SD-WAN）、上云专线（Cloud VPN）、
 上网连接（5G/NB-IoT）。
13. **协议家族**：现场总线 8 个、工业以太网 4 个、工业无线 8 个；异构互通三招（网关/适配器/
 格式转换）。
14. **5G 五指标**：1 百万/km²、1 Gbit/s、1 ms、99.9999%、1 μs；三技术：高频多天线、网络切片、
 边缘计算。
15. **TSN**：IEEE 802.1 增强标准、确定性通信；四问题四机制；**全局时钟 + 传输调度器**。
16. **边缘计算**：四类核心能力、三层功能视图、四大功能（自动控制/分析/优化/感知执行）、
 三大能力（计算/网络/存储）。
