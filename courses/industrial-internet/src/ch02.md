# 第二章 · 一张蓝图

上一章收在"一地零件"：感知、联网、云、大数据、安全。我们决定先别空想，先干件实事——把那张表上的"48 小时追溯"，落成一次。

## 一个追不动的零件

你从仓库里翻出上个月的零件，想把它的一生从头到尾还原出来：哪台机床、哪个批次、哪把刀具、什么时候下的料。

第一步就卡住了：名字对不上。

- 采集系统里，这台机床叫 "Machine-07"；
- ERP 里，它叫 "A07 加工中心"；
- 客户的资产台账里，它叫 "X-3321"。
- 刀具更糟：MES 记的是 "T-88"，机床自己的日志却写"3 号刀位"。

同一个东西，三个系统三个名字。你手里攥着三份记录，却拼不出一条线——缺的正是那条共享的"谁是谁"的主线。"48 小时追溯"，你连"这个零件是不是 Machine-07 上做出来的"都赌咒不了。

这一下把你敲醒了：此前每一块零件，都是在各自的孤岛里搭起来的，没人想过它们得画到同一张图纸上对齐。问题不出在某一"块"，而出在*整体*。我们缺的不是更多零件——是一张图纸，说清它由什么构成、各部件怎么协作。

## 先把话说明白：到底有几件大事？

先别急着画线。你把那堆零件摊开，发现其实只有三件大事：

- **网络**：把设备连起来、让数据流动——是基础；
- **数据**：一旦连上，每一分价值都由它驱动——是引擎；
- **安全**：别让前两样炸掉——是保险。

这就是三大核心：**网络、数据、安全**。网络是基础支撑，数据是核心驱动，安全是必要保障。顺着这三样，你还要再叠一层优化：围绕**一台机器**怎么优化、围绕**一条产线**怎么优化、围绕**一家企业**怎么优化——从单台设备一路放大到企业经营的三个闭环。

可写着写着，你就别扭了：数据跟另外两样纠缠不清。网络运的是数据，安全护的是数据，数据本身又是核心——三者都绕着"数据"转，职责分不开。

于是你改：把**平台**单拎出来，承接数据的集成、管理与建模。现在三个词各管一摊：**网络管"连"，平台管"算"，安全管"保"。**这就是 1.0 到 2.0 的关键一改——用*平台*替换了*数据*。

回看走过的路，你其实爬了三级台阶：**数字化**（先做单点优化——看懂一台机器）→ **网络化**（再做全面互联——连起整个工厂）→ **智能化**（最后全局智能——让数据替你拍板）。

三大体系还不够，你还得有一套*方法*，规定"怎么设计"，否则又是拍脑袋画线。方法就是三个问题：

1. **干什么？**——业务视图（目标、方向、场景、能力）；
2. **需要什么能力？**——功能架构（核心功能、原理、要素）；
3. **怎么落地？**——实施框架（层次结构、软硬件、部署）。

先定业务目标，再定功能，最后落地。顺序反了，就得推倒重来。

## 业务视图：你在替谁说话？

"干什么"也不是"数字化"一个词能盖住的。你把镜头拉远又拉近，发现要看四个层次：

- **产业层**：宏观——整个产业怎么完成数字化转型；
- **商业层**：微观——单个企业的业务与商业模式；
- **应用层**：微观——落到哪些应用场景；
- **能力层**：微观——那些场景需要哪些数字化能力。

只有产业层是宏观；其余三层，都是企业的微观视角。

## 功能架构：一张"4 层 × 3 体系"的矩阵

"需要什么能力"是本章的重头戏。先立一句贯穿全章的话——工业互联网的**核心功能原理**，是基于数据驱动的物理系统与数字空间全面互联与深度协同，以及在此过程中的智能分析与决策优化。翻译成人话：给真实的工厂造一个实时同步的"数字影子"，让两边互通，再用数据把真实工厂调回去。

主线立住了，再展开成三个功能视图。妙就妙在：这三张视图你其实都见过——就是上一章攒下的零件，各自归位。

**网络体系 = 网络互联 + 数据互通 + 标识解析。**

- **网络互联**：把要素连起来、承载传输——上一章的现场总线、5G、LPWAN 都归这儿；
- **数据互通**：让要素互相"听得懂"——上一章记在账上的"说得上话"（格式不一）问题，就是它来管，经 OPC UA、MQTT 等协议统一信息模型；
- **标识解析**：给要素一个"注册过的身份"——标记、管理、定位。还记得开头那个追不动的零件吗？"Machine-07""A07 加工中心""X-3321"三个名字，缺的正是这一步：给每个东西一个全系统唯一、公认的标识，让谁查到的都是同一个"它"。

一句话记住顺序：**连 → 懂 → 找。**

**平台体系 = 边缘层 + PaaS 层 + 应用层。**

- **边缘层**：在最靠近设备的地方，做接入、转换、预处理和边缘分析；
- **PaaS 层**：资源管理、数据与模型管理、建模分析、应用创新；
- **应用层**：工业应用、开发者社区、应用商店。

对照上一章的云计算：边缘层干"就近先算一遍"的活，PaaS 层就是云的平台层，应用层是最终交付的功能。

**安全体系 = 五大安全：可靠性、保密性、完整性、可用性、隐私和数据保护。**

相比互联网经典的 CIA 三要素（保密性、完整性、可用性），多了两个——**可靠性**（工业系统不能宕机）和**隐私和数据保护**。多的这两个，恰恰是"工厂"与"互联网"安全需求的分水岭。

把三张视图摞起来，再纵向切成四层——**设备层、工厂层、企业层、产业层**——就得到那张"4 层 × 3 体系"的总图。能凭记忆把它重画出来，本章的骨架你就拿下了。

## 实施框架：四个可落地系统

"怎么建"反而是最省事的：把能力落到地上，就是四个可落地的系统——**网络系统、标识系统、平台系统、安全系统**。

注意，是"标识系统"，不是"数据系统"：到落地这一步，标识解析被单拎出来、成了一个可立项的工程——因为它是开头"名字对不上"那个问题的根。从蓝图到施工图，这是最后一步。

## 收个尾

回到开头那个零件。有了这张蓝图，它的命运就清楚了：

- 三个对不上的名字 → **标识解析**给它一个全系统唯一的身份；
- 三份格式不同的记录 → **数据互通**统一措辞；
- 数据在哪处理、OEE 怎么算 → 全在**平台**里；
- 让整条链不被黑 → **安全**兜底。

一句话：网络是基础、平台是核心、安全是保障；先定干什么，再定要什么能力，最后才定怎么建。而具体的网络、平台、安全——各自怎么建——是后面几章的活。
