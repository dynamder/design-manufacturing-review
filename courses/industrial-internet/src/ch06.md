# 第 6 章 安全技术

> 本章对应课件《第 6 章 工业互联网的安全技术》（共 77 页）。
> 图例：加粗 = 课件原文中以红色（深红或纯红）标出的内容，句尾〔标红 C6·Py〕标注来源页。本文不用加粗表达其他强调。

本章回答"工业互联网为什么危险、该怎么防"。主线是四步递进：先用震网病毒确立"网络攻击可以造成物理破坏"这一前提，再给出安全框架（横向五个安全域、纵向四个层级），然后按设备、控制、网络、应用、数据五个维度逐层列出防护技术，最后以工业区块链作为面向跨企业协作的新兴技术收尾。

## 6.1 安全威胁

### 6.1.1 震网病毒（Stuxnet）：第一个打到真实世界的蠕虫

2010 年曝光的震网病毒（Stuxnet 蠕虫，又称"超级工厂病毒"）是**首个**专门针对**工业控制系统**的破坏性蠕虫病毒〔标红 C6·P5〕。

它的目标是伊朗纳坦兹（Natanz）核工厂的铀浓缩离心机，借西门子工控系统的漏洞实施破坏，造成大批浓缩铀离心机故障，伊朗核工业一度陷入停滞，入侵最终成功〔C6·P5〕。病毒是在客户机器反复异常重启、追查蓝屏原因时被发现并上报的，报告者是白俄罗斯安全研究员 Sergey Ulasen 及其团队〔C6·P5〕。

课件因此把它定性为全球第一个主动攻击真实世界基础设施的蠕虫病毒〔C6·P6〕。由此得出本节最重要的一条判断：**网络攻击可对现实世界的工业设备造成物理破坏**〔标红 C6·P6〕。

> 两个"第一"说的是两件不同的事：P5 的"首个"限定的是攻击目标类型（工业控制系统），P6 的"全球第一个"限定的是攻击对象性质（真实世界的基础设施）。但两个判断都落在"蠕虫"上——蠕虫不需要人点击、能自行复制传播，这才是它能穿过空气隔离、从一台机器爬到另一台机器的前提；说成"病毒"会丢掉这层含义。

课件的攻击路径六步〔C6·P7〕：

1. 感染——通过 U 盘等移动介质进入物理隔离的内网，先感染 Windows 主机；
2. 扫描——在内网探测使用西门子控制软件的工程师站与 PLC；
3. 更新——连上外部命令与控制服务器下载新版本，保证自身不被查杀；
4. 破坏——向目标 PLC 下发篡改后的控制逻辑，让离心机转速异常；
5. 控制——潜伏、隐藏痕迹，维持对目标系统的长期控制；
6. 欺骗、摧毁——向监控画面回放正常数据骗过操作员，同时让离心机反复超速、失速直至损毁。

六步里最值得注意的不是"破坏"，而是"欺骗"：设备在物理上已经被毁，操作员看到的曲线却一切正常。这说明工业安全的对抗点不止在"能不能进来"，还在"进来了能不能被发现"。

### 6.1.2 漏洞形势与三个思考

课件给出的一年数据：网络安全漏洞总数达 48482 条，同比增长 21.1%；其中**工控系统漏洞** 864 条，同比上升 13.2%〔标红 C6·P9〕。针对工业控制系统的攻击集中在电力、化工、石油、铁路、新能源、核应用等关键领域，关系到国家经济命脉〔C6·P9〕。数量上工控漏洞只占约百分之二，但每一条都落在不能停机、不能断电的场景里。

由震网引出三个思考〔C6·P10〕：

- 物理隔离不等于安全；
- 安全机制薄弱；
- 单一防护措施极易被突破。

> 第一条的现实依据就在震网本身：隔离网络仍必须靠移动介质、供应链和运维笔记本与外界交换数据，震网的 U 盘入口正是这么来的〔C6·P7〕。隔离还有两个副作用——补丁进不去，漏洞长期留存；缺少监测手段，入侵被发现得更晚。所以隔离是降低概率的手段，不是安全保证。

### 6.1.4 其他工业互联网安全事件

课件排了一条 2010—2023 年的工业安全事件时间轴〔C6·P8〕：起点是 2010 年的震网，其后有 2015 年与 2016 年乌克兰电网两度遭攻击导致大面积停电、2017 年 WannaCry 勒索蠕虫使多家制造企业停产、2021 年美国 Colonial Pipeline 输油管道因勒索软件停运。这些事件的共同点是攻击直接落在生产与运行系统上，而不是停在办公网。

## 6.2 安全框架

### 6.2.1 横向五个安全域，纵向四个层级

工业互联网安全包括五个维度：**设备安全**、**控制安全**、**网络安全**、**应用安全**、**数据安全**〔标红 C6·P13〕。

![图 6-2 工业互联网安全框架：设备/控制/网络/应用/数据五维 + 新兴技术（课件 C6·P13）](assets/figs/c6_framework.jpg)

*图 6-2 工业互联网安全框架：设备/控制/网络/应用/数据五维 + 新兴技术（课件 C6·P13）*

这张框架图有两个方向，读图时不能只看横向：

- 横向是五个安全域——设备、控制、网络、应用、数据，另加一栏新兴技术〔C6·P13〕；
- 纵向是四个层级——产业层、企业层、工厂层、设备层〔C6·P13〕。

纵向四层回答"看哪一层的安全"，横向五维回答"看哪一类安全域"。同一项技术在两层里含义不同：设备层关心固件与接口，企业层关心云平台、供应链与跨厂区数据；把维度当成层次来套，就会出现"给产业层配一个防火墙"这种错位。

各维度的覆盖范围〔C6·P14〕：

| 维度 | 覆盖对象 |
| --- | --- |
| **设备安全** | 工业机器人、智能仪表、传感器等 |
| **控制安全** | 控制软件、控制协议等 |
| **网络安全** | 工厂内、外部网络及边界 |
| **应用安全** | 工业互联网平台与工业应用程序两大类 |
| **数据安全** | 工厂内部、外部数据及用户信息 |

框架右侧还有一栏新兴技术：人工智能、区块链、可信计算、零信任〔C6·P13〕。这一栏不是第六个安全域，而是可以渗透进各个安全域的技术手段。

### 6.2.2 五个维度的变化与安全分析

五个维度的讲法完全同构：先讲本维度发生了哪些变化，再讲变化带来的新挑战，最后才落到技术（§6.3–§6.7）。

#### （1）设备安全

设备变化：现场设备由机械化向**智能化**发展，新模式是嵌入式操作系统（**EOS**）+ 微处理器 + 应用软件〔标红 C6·P15〕。课件举的例子是传统车床、铣床变成数控车床、数控铣床。

设备安全分析的四点〔C6·P16〕：

- 扩散速度增加——同型号设备装着同样的固件，一处恶意代码可在短时间内复制到成群设备；
- 攻击直达设备——攻击不再止于上位控制系统，可越过上位机直接落到智能设备本体；
- 攻击范围扩大——设备联网后，一台设备出问题会牵连整条产线乃至多个厂区；
- 漏洞影响扩大——影响面从特定型号设备扩大到海量通用设备。

> 这四点合起来解释了一个反直觉的现象：设备"变聪明"的同时，可攻击面也一起变大。机械化设备只能被物理破坏，智能化设备还可以被远程改写。

#### （2）控制安全

控制变化〔标红 C6·P17〕：

- **生产控制**：分层、封闭、局部 → 扁平、开放、全局；
- **控制环境**：**IT** 与 **OT** 融合，控制网络由封闭走向**开放**；
- **控制布局**：控制范围从局部到**全局**，控制监测上移、实时控制下移。

工业控制系统（**Industrial Control Systems, ICS**）主要包括 SCADA 系统、DCS、PLC 以及其它控制系统〔标红 C6·P17〕。

> "扁平"是**扁平化管理**：通过减少管理层次、压缩职能部门和机构，使决策层与操作层之间的中间层级尽可能减少，以便把决策权快速延至生产、营销最前线；与之相对的是传统的**金字塔管理模式**〔标红 C6·P18〕。控制系统从金字塔变成扁平，中间层的隔离与缓冲随之消失。

控制安全分析三点〔C6·P19〕：

1. 攻击从 **IT** 层渗透到 **OT** 层，OT 层不再可信；
2. OT 层的**控制协议**、**软件安全**机制缺失，攻击难度大大降低；
3. 信息安全与功能安全交织。

> 第三条是工业安全与 IT 安全最大的差别。功能安全关心"设备别伤人"，信息安全关心"系统别被攻破"，而防护措施本身会动功能安全：给 PLC 打补丁要停机，加防火墙会增加时延，加密会拖慢实时控制。因此工业安全不能照搬 IT 那套"先关掉再修"，必须在线、不中断生产、可回滚。

#### （3）网络安全

网络变化〔标红 C6·P20〕：

- 工厂内网呈现 IP 化、无线化，组网方式灵活化、全局化；
- **IT** 信息网络与 **OT** 控制网络逐渐融合，企业**专网**与**互联网**逐渐融合；
- 传统互联网的安全问题向工业互联网蔓延。

协议谱系随之翻转：一侧是**专有协议**（有线通讯协议、无线通讯协议、现场总线协议），另一侧是**工业以太网协议**、**工业无线网络协议**〔标红 C6·P22〕。

网络安全分析三点〔标红 C6·P21〕：

1. 工业互联协议由专有协议向**以太网/IP协议**转变，攻击门槛极大降低；
2. 工业以太网交换机性能低，易受**分布式拒绝服务攻击**；
3. 工厂网络的互联、生产、运营由静态转为**动态**，安全策略面临挑战。

> **DDoS攻击**：通过大量受控设备向目标系统发送海量请求，使其无法为正常用户提供服务〔标红 C6·P21〕。工控交换机性能低，几百兆的流量就足以顶满，不需要多大规模。

> 专有协议"不通用"本身就是一层防护：工具少、懂的人少、攻击门槛高。改用公开的以太网/IP 协议后，IT 世界积累的工具与攻击方法可以整套搬过来——这是开放性的代价。

#### （4）应用安全

应用变化：应用安全包括**平台**与**应用程序**两大类；覆盖智能化生产、网络化协同、个性化**定制**、服务化**延伸**等方面；具体形态是设计协同、供应链协同、制造协同、服务协同与用户全流程参与〔标红 C6·P23〕。

工业互联网具备多用户、多设备、多平台、多工序、数据来源多、类型多、跨组织、跨区域等特点，这些特点本身就构成安全挑战〔C6·P24〕。

应用安全分析三点〔标红 C6·P25〕：

1. 不同业务的**安全保护需求**不同；
2. 网络安全**隔离能力**要求高；
3. 业务应用的**安全保障能力**要求高。

#### （5）数据安全

数据变化最直观：数据由少量、单一、单向转向大量、多维、**双向流动**；体量增大、种类增多、结构复杂；工厂内外网络双向流动共享〔标红 C6·P26〕。

**数据安全**分析四点〔标红 C6·P27〕：数据泄露风险增大、数据保护难度增大、数据价值保护需求、用户隐私数据可能泄露。

> 单向流动时数据只从设备流向平台，出不了厂门；双向共享后数据要跨越企业边界，交给供应链、客户与第三方应用。边界一破，风险从"会不会丢"变成"谁在用、用到哪、怎么收回"。

## 6.3 设备安全防护技术

设备侧有四类技术〔C6·P29–31〕。

① 固件攻击面减少（Firmware Attack Surface Reduction，FASR）——从操作系统内核、协议栈做安全增强，阻止恶意代码传播与运行〔C6·P29〕。固件（Firmware）是存储在**硬件设备**中的特殊软件，直接控制设备底层操作，充当硬件与高级软件（如操作系统）之间的桥梁〔标红 C6·P29〕。

② **漏洞修复**与**补丁管理**〔标红 C6·P30〕——这是两件事：

| 项目 | 内容 |
| --- | --- |
| **漏洞修复** | 修复设备中存在的漏洞和安全弱点。流程：设备发现 → 漏洞扫描 → 漏洞评估 → 漏洞修复 |
| **补丁管理** | 对补丁全流程的管理：检测 → 下载 → 测试 → 批准 → 安装 |

> 顺序值得留意：检测、下载之后要先测试、再批准，最后才安装。工业现场不能拿生产系统试错，所以"测试"和"批准"必须卡在"安装"之前；补丁一旦装错，停机损失远大于漏洞本身。

③ 硬件安全增强——对**硬件**进行**标识**；把硬件级部件（安全芯片或安全固件）作为系统信任根〔标红 C6·P31〕。

④ 运维管控——对外部存储器等**硬件连接设备**的使用进行管控；部署运维管控系统〔标红 C6·P31〕。

## 6.4 控制安全防护技术

控制侧按框架图的两列展开：控制协议安全与控制软件安全〔C6·P13〕。

### 6.4.1 控制协议安全（五项）

| 技术 | 内容 |
| --- | --- |
| **身份认证** | 主要通过**知识类**认证、**资产类**认证、**本征类**认证的组合方式实现，确保控制系统执行的控制命令来自合法用户〔标红 C6·P33〕 |
| 白名单技术 | 建立工业控制协议白名单访问控制策略，过滤一切非法访问，保证只有白名单内的可信任指令和消息才能在网络上传输〔C6·P34〕 |
| **访问控制** | 鉴别访问主体的合法身份后，通过某种途径**准许**或**限制**用户对数据信息的访问能力及范围，从而控制对关键资源的访问〔标红 C6·P34〕 |
| **传输加密** | 三种手段：在协议栈增加**安全层**、在协议应用数据单元增加**安全字段**、改进通信会话的**过程**〔标红 C6·P35〕 |
| **脆弱性测试**（**漏洞评估**） | 一种系统化识别系统、网络、应用中安全弱点的**安全检测方法**，通过量化分析潜在威胁并提出修复建议，是漏洞管理与风险管理的核心环节〔标红 C6·P36〕 |

身份认证的三种方式对应三个问题：知识类问"你知道什么"，资产类问"你拥有什么"，本征类问"你是谁"。三者组合而不是单选，是因为单一因子在工控现场很容易被旁路获取。

脆弱性测试中，Fuzzing test（模糊测试）占 80%，模糊测试又分黑盒、白盒、灰盒三种类型〔C6·P37〕。它之所以占这么高比重，是因为工控协议大量是二进制私有格式，靠读文档找不到边界条件，只能靠大量畸形输入去撞。

白名单与访问控制的区别在于默认态度：白名单默认拒绝、只放行已知可信的指令与消息；访问控制默认先认证身份，再按权限范围决定准许还是限制。

### 6.4.2 控制软件安全（四项）

| 技术 | 内容 |
| --- | --- |
| **软件防篡改** | 以代码测试、完整性校验、代码加密等方式，防止攻击者篡改工业控制软件〔标红 C6·P38〕 |
| **恶意软件防护** | 恶意代码检测、预防和恢复〔标红 C6·P39〕 |
| 认证授权、漏洞修复和补丁升级 | 传统手段，但要求在线、不中断生产〔C6·P40〕 |
| **安全监测与审计** | 利用特定**工业软件**操作的周期性，测量协议不同阶段执行中的**偏差**；利用控制软件中的**时间序列信息**，基于无监督学习的方法进行**异常检测**〔标红 C6·P41〕 |

> 为什么控制软件的安全监测要用无监督学习？因为工业现场几乎没有带标签的攻击样本（不能拿生产线做实验），而正常行为高度规律、周期性强。样本只有"正常"一类，就只能"学正常、报异常"。

## 6.5 网络安全防护技术（五项）

| 技术 | 内容 |
| --- | --- |
| **网络隔离** | 限制网络之间的资源共享，防止信息泄露。典型场景：工厂内外网隔离、生产网与办公网隔离、工业控制系统隔离。包括**物理隔离**、**协议隔离**、**应用隔离**〔标红 C6·P43〕 |
| **边界管控** | 在**网络边界**上部署可靠的安全防御设备，对**安全域边界**进行监视，识别边界上的入侵行为并进行有效阻断（如现场控制级环境、线路调控环境、运营管理系统环境之间的边界）〔标红 C6·P44〕 |
| **接入管理** | 对接入的设备与标识解析节点进行**身份认证**，保证合法接入和合法连接〔标红 C6·P45〕 |
| **通信和传输保护** | 加密技术、校验机制〔标红 C6·P46〕 |
| **入侵检测系统**（IDS） | 通过**网络流量**分析，实现网络流量监测与告警。两类方法：基于**规则库**（预先定义模式或与已知恶意序列比对）与基于**异常**（早期用机器学习，当前用深度学习，用大规模神经网络参数挖掘训练样本背后的知识）〔标红 C6·P47〕 |

网络隔离的三级是物理隔离、协议隔离、应用隔离——按"断开物理链路 → 只放行特定协议 → 只在应用层做过滤"逐级放松，隔离强度依次下降、可用性依次上升。

IDS 的两种方法是一对互补：规则库认得已知的坏，异常检测认得未知的怪。工控协议种类多、私有格式多，规则库覆盖不全，所以基于异常的深度学习方法在工业场景里更被看重。

## 6.6 应用安全防护技术

应用安全分**平台安全**与**工业应用程序安全**两大类〔标红 C6·P49〕。

### 6.6.1 平台安全（六项）

| 技术 | 内容 |
| --- | --- |
| 安全审计 | 记录、审查平台上的操作行为 |
| 认证授权 | 身份鉴别与权限分配 |
| 安全隔离 | 多租户、多应用之间的隔离 |
| 安全监测 | 运行状态与异常监测 |
| 补丁升级 | 平台组件漏洞修补 |
| **DDoS 防御** | 基于负载均衡、内容分发网络（CDN）、分布式集群防御等手段〔标红 C6·P50〕 |

六项技术在同一页列出〔C6·P50〕。平台安全的特点是"面上防护"：平台同时承载多用户、多设备、多应用，任何一项都不针对某个具体漏洞，而是维持整个平台的可管、可控、可用。

### 6.6.2 工业应用程序安全（五项）

工业应用程序安全共五项，含代码审计、补丁升级、脆弱性检测、审核测试、行为监测及异常阻止〔C6·P49〕：

| 技术 | 内容 |
| --- | --- |
| **代码审计** | 检查源代码中的缺点和错误信息，分析并找到这些问题引发的安全漏洞〔标红 C6·P51〕 |
| 补丁升级 | 对已发布应用修补漏洞〔C6·P49〕 |
| **脆弱性检测** | 基于漏洞数据库或 APP 逆向等技术手段，对工业应用程序进行漏洞发现〔标红 C6·P52〕 |
| 审核测试 | 上线前的合规与安全测试〔C6·P49〕 |
| **行为监测及异常阻止** | 基于静态行为规则匹配或机器学习的方法〔标红 C6·P53〕 |

代码审计看的是源代码（白盒），脆弱性检测看的是已编译的程序（漏洞库加逆向），行为监测及异常阻止看的是运行时的行为。三者对应开发、发布、运行三个阶段。

## 6.7 数据安全防护技术

### 6.7.1 按数据所处环节的三类传统防护

| 环节 | 技术 |
| --- | --- |
| **数据传输** | 数据加密 |
| **数据处理** | 数据敏感性识别、使用授权、数据脱敏 |
| **数据存储** | 访问控制、存储加密 |

三个环节共六项技术：传输加密、敏感性识别、使用授权、数据脱敏、访问控制、存储加密〔标红 C6·P55〕。

> "传加密、用授权、存控制"——数据在路上的时候防被截，在手里用的时候防越权，落地存放的时候防被拖库。三个环节的风险不同，手段也不同：路上靠密码学，用时靠权限模型，存放靠访问控制加存储加密。

### 6.7.2 基于新兴技术的四类防护

| 技术 | 作用 |
| --- | --- |
| 基于**人工智能** | 数据智能识别保护、智能安全溯源、智能风险预警、智能精准管控〔标红 C6·P56〕 |
| 基于**区块链** | 数据安全存储和可信交换共享〔标红 C6·P57〕 |
| 基于**可信计算** | 确保数据可信、可控、可管〔标红 C6·P58〕 |
| 基于**零信任架构** | 数据可信访问〔标红 C6·P59〕 |

可信计算（Trusted Computing）是通过硬件和软件协同工作，确保计算设备、数据和应用程序在任何情况下都能按预期安全运行的技术体系〔标红 C6·P58〕。零信任架构的原则是"永不信任、持续验证"：不再默认内网可信，每一次访问都要重新验证身份与权限。

## 6.8 工业区块链技术

### 6.8.1 区块链基础

**区块链（Blockchain）**是一种由区块（block）组成的**链式数据结构**，并且是**去中心化**的、**不可篡改**的分布式账本技术：通过链式数据结构记录交易和信息，实现数据的透明和安全〔标红 C6·P61〕。

课件 P61 的图用包含关系说明层次：比特币属于区块链，区块链属于分布式数据库〔C6·P61〕。所以"区块链 = 比特币"是错的——比特币只是区块链上的一个应用，区块链是更底层的技术。

安全性来自两样东西：哈希算法（提供唯一性、不可篡改性）加加密密钥（公钥/私钥，共同决定整体安全性）〔C6·P62〕。

区块链的五个特性〔C6·P63〕：

| 特性 | 含义 |
| --- | --- |
| 透明性 | 账本公开可查 |
| 不可篡改性 | 哈希链式结构保证 |
| 去中心化 | 无单一中心机构 |
| 可追溯性 | 每笔记录可回溯 |
| 减少交易成本和时间 | 去掉中间对账环节 |

典型应用场景：金融服务、供应链管理、医疗保健、数字身份认证、投票系统、智能合约〔C6·P63〕。

### 6.8.2 工业区块链的特征

课件把工业区块链的特征归为四条〔标红 C6·P64〕：

| 特征 | 内容 |
| --- | --- |
| **技术基础** | 数字签名、时间戳、分布式共识及多方存储、智能合约自动执行 |
| **功能特色** | 多中心化信任构建、跨组织高效协作、可控安全共享、可追溯审计防篡改 |
| **应用领域** | 在多方可信安全存证、业务协同全过程留痕、资产盘点监管治理等领域具有显著优势 |
| **链网协同** | 区块链—工业互联网协同，势在必行 |

四条的顺序本身是一条逻辑链：先有技术基础，才有功能特色；功能特色决定它能用在哪些领域；而在工业场景，区块链与工业互联网必须协同演进，单建链或单建网都不成立。

> 工业场景为什么需要它：工业互联网的协作要跨企业，而跨企业之间没有共同的信任中心；区块链用分布式账本加智能合约，在不依赖第三方的前提下建立信任，正好补上多主体协作这块短板。

### 6.8.3 四个解决方案

工业互联网面临四类难题，工业区块链一类对一类地给出解决方案〔C6·P65〕：

| 挑战 | 基于工业区块链的解决方案 |
| --- | --- |
| 信任构建难 | 工业互联网分布式信任管理 |
| 数据确权流转难 | 工业互联网数据确权流转管理 |
| 数据安全共享难 | 工业互联网数据安全共享管理 |
| 事件审计追溯难 | 工业互联网事件审计追溯管理 |

（1）**工业互联网分布式信任管理**〔标红 C6·P66〕——针对多平台、多设备、多用户、多工序协作中缺乏统一可信身份认证的问题〔C6·P66〕，三个手段：

- 联盟数字身份表示方法：实现人机物多类型实体的快速标记（联盟身份 ID = 联盟分布式数字身份标识 + 联盟身份凭证，一个实体可生成多个联盟身份 ID 对应不同场景的凭证）〔C6·P66〕；
- 联盟数字身份**全生命周期管理**：实现身份自生成、自存储、自销毁，注册 → 验证 → 更新 → 撤销四步都在账本上留痕〔标红 C6·P67〕；
- 重要属性隐私保护机制：实现跨联盟协同许可认证，分四级（身份 ID 生成 → 身份凭证生成 → 身份区块生成 → 身份验证）〔标红 C6·P68〕。

（2）**工业互联网数据确权流转管理**〔标红 C6·P69〕——针对数据来源多、流转权属关系确认难、使用责任不清晰的问题〔C6·P69〕：

- 内外因素联合抽取轻量化数据资产身份标签并上链，满足海量唯一标记需求〔C6·P69〕；
- 联盟分布式账本上数据资产与标签身份绑定，支持跨域多方数字资产链下链上连通和确权存储〔标红 C6·P70〕；
- 构建**隔离通道**和**流转共识**策略的**访问控制机制**，支撑非授权流转阻断〔标红 C6·P71〕。

（3）**工业互联网数据安全共享管理**〔标红 C6·P72〕——针对原始数据共享意愿低、加密数据计算过程过于透明且难追踪的问题〔C6·P72〕：

- 联盟分布式多方密文同态计算，支持原始数据密文共享及计算方密文计算过程不透明〔标红 C6·P72〕；
- 联盟计算方安全激励协同机制，支持数据计算方**全阶段留痕追踪**和共享结果**正向激励**〔标红 C6·P73〕。

目标是实现可追踪的"数据模型共享、数据不可见"创新业务模式：模型能流动，原始数据不出域。

（4）**工业互联网事件审计追溯管理**〔标红 C6·P74〕——针对跨组织跨区域互通联动后缺乏统一高效的追溯审计手段的问题〔C6·P74〕：

- **建立事件可信共享渠道**，实现跨域事件信息定期及时上链〔标红 C6·P74〕；
- **生成区块链上事件映射逻辑链**，支持完成不同阶段到原始事件发生点的审计追溯〔标红 C6·P75〕；
- **智能合约自主执行机制**，支持事件行为簇以时间为单位打包审计报告的共享查阅，以及审计数据的自动化标注和更新〔标红 C6·P76〕。

## 本章小结

- 震网病毒：首个专门针对工业控制系统的破坏性蠕虫，目标为伊朗纳坦兹核工厂离心机；全球第一个主动攻击真实世界基础设施的蠕虫病毒；攻击路径六步为感染、扫描、更新、破坏、控制、欺骗与摧毁。
- 三个思考：物理隔离不等于安全、安全机制薄弱、单一防护措施极易被突破。
- 漏洞形势：总数 48482 条、同比增 21.1%；工控系统漏洞 864 条、同比升 13.2%；攻击集中在电力、化工、石油、铁路、新能源、核应用。
- 五类威胁（并列）：设备、控制、网络、应用、数据；设备安全、控制系统安全、数据安全尤为急迫。
- 安全框架：横向五个安全域，纵向产业层、企业层、工厂层、设备层四层，另有新兴技术一栏。
- 五维变化：设备机械化转智能化（EOS + 微处理器 + 应用软件）；控制由分层封闭局部转扁平开放全局；网络 IP 化无线化、IT 与 OT 融合；应用含平台与工业应用程序两类；数据由少量单一单向转大量多维双向流动。
- 设备防护四类：固件攻击面减少（FASR）、漏洞修复与补丁管理、硬件安全增强（信任根）、运维管控；补丁管理流程为检测、下载、测试、批准、安装。
- 控制防护两侧：协议侧五项（身份认证、白名单、访问控制、传输加密、脆弱性测试，Fuzzing 占 80%）；软件侧四项（软件防篡改、恶意软件防护、认证授权与补丁升级、安全监测与审计）。
- 网络防护五项：网络隔离（物理、协议、应用）、边界管控、接入管理、通信和传输保护、入侵检测（规则库、异常）。
- 应用防护两类：平台安全六项（安全审计、认证授权、安全隔离、安全监测、补丁升级、DDoS 防御）；工业应用程序安全五项（代码审计、补丁升级、脆弱性检测、审核测试、行为监测及异常阻止）。
- 数据防护：传输加密；处理阶段的敏感性识别、使用授权、脱敏；存储阶段的访问控制与存储加密；新兴技术为人工智能、区块链、可信计算、零信任架构。
- 区块链：由区块组成的链式数据结构，去中心化、不可篡改的分布式账本；特性为透明性、不可篡改性、去中心化、可追溯性、减少交易成本和时间。
- 工业区块链特征四条：技术基础、功能特色、应用领域、链网协同。
- 工业区块链四方案：分布式信任管理、数据确权流转管理、数据安全共享管理、事件审计追溯管理。
