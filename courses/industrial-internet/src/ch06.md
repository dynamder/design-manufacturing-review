## 1 安全威胁（6.1）

### 1.1 震网病毒（Stuxnet）：本课程的"第一案例"

<strong>攻击路径六步</strong>：

"震网病毒事件的警示意义"（课后题 1）——四点：① <strong>攻击目标变了</strong>：从"偷数据"变成"毁设备"，网络攻击有了<strong>物理破坏力</strong>；② <strong>物理隔离失效</strong>：病毒通过 U 盘/供应链等<strong>离线途径</strong>进入内网，说明"隔离"只是降低概率，不是安全保证；③ <strong>单点防护不够</strong>：一个漏洞（西门子 PLC 的配置软件）就能穿透整个体系，必须<strong>纵深防御</strong>；④ <strong>IT 与 OT 融合是双刃剑</strong>：融合带来效率，也把 IT 的攻击面引到了 OT。

### 1.2 形势与三个思考

"为什么物理隔离不等于安全"——三条理由：① 隔离网络仍需<strong>移动介质/供应链/运维笔记本</strong>进出（震网就是走 U 盘）；② 隔离导致<strong>补丁无法及时更新</strong>，漏洞长期留存；③ 隔离让人<strong>放松警惕</strong>，缺乏监测手段，被入侵后<strong>发现更晚</strong>。

### 2.2 五维的"变化"与"安全分析"

#### （1）设备安全

"设备变智能了，为什么反而更不安全"——"三化"带来的三个后果：<strong>有 OS 就有漏洞</strong>（EOS 可被攻击）、<strong>有网络就有入口</strong>（联网设备可被远程攻击）、<strong>有软件就能刷</strong>（固件可被篡改）。再补一句"同型号设备海量同构，一个漏洞影响一大片"。

#### （2）控制安全

> 【补充·课件 C6·P18】"扁平"指<strong>扁平化管理</strong>：通过<strong>减少管理层次、压缩职能部门和机构</strong>，
> 使决策层与操作层之间的中间管理层级尽可能减少，以便快速把决策权延至生产、营销最前线；
> 对应的是传统的<strong>金字塔管理模式</strong>。

信息安全与功能安全交织：功能安全关心"设备别伤人"，信息安全关心"系统别被攻破"。两者交织体现在：<strong>安全防护措施本身可能影响功能安全</strong>（比如给 PLC 打补丁要停机、加防火墙会增加时延、加密会拖慢实时控制）。所以工业安全不能照搬 IT 的"先关再修"，必须<strong>在线、无损、可回滚</strong>。这句话是高分点。

#### （3）网络安全

> 【补充·课件 C6·P21】DDoS（Distributed Denial of Service，分布式拒绝服务攻击）：通过大量
> 受控设备向目标系统发送海量请求，使其无法为正常用户提供服务。

"为什么工业协议改用以太网/IP 后更危险"——因为<strong>协议公开、工具丰富、攻击门槛低</strong>；专有协议虽然不通用，但"不透明"本身就是一层防护。这是"开放性"的代价。

#### （4）应用安全

应用安全的两个大类：<strong>工业互联网平台安全</strong> + <strong>工业应用程序安全</strong>（第 6 章§6 就按这两类展开）。

#### （5）数据安全

> 【课件 C6·P26】<strong>数据变化</strong>：
> - <strong>少量、单一、单向 → 大量、多维、双向</strong>转变；
> - 数据<strong>体量增大、种类增多、结构复杂</strong>；
> - <strong>工厂内外网络双向流动共享</strong>。

"数据从单向变双向，风险为什么变大"——单向（设备→平台）时数据只在内部流动；双向共享后，数据要<strong>出企业边界</strong>（给供应链、给客户、给第三方 App），于是多了三个风险：<strong>谁在用（越权）、用到哪（出境/出界）、怎么删（生命周期）</strong>——正好对应后面 §7 的"访问控制、脱敏、生命周期管理"。

## 3 设备安全防护技术（6.3）

| 技术 | 内容 |
| --- | --- |
| <strong>① 固件攻击面减少（Firmware Attack Surface Reduction，FASR）</strong> | 从<strong>操作系统内核、协议栈</strong>做安全增强，<strong>阻止恶意代码传播与运行</strong>。<strong>固件（Firmware）</strong>：存储在硬件设备中的特殊软件，直接控制设备底层操作，充当<strong>硬件与高级软件（如操作系统）之间的桥梁</strong> |
| <strong>② 漏洞修复与补丁管理</strong> | 流程：<strong>设备发现 → 漏洞扫描 → 漏洞评估 → 漏洞修复</strong>（配套"安装—下载—测试—批准—监测"的补丁流程）。<strong>漏洞修复</strong>：修复设备中存在的漏洞和安全弱点；<strong>补丁管理</strong>：补丁的<strong>检测、下载、测试、批准和安装</strong> |
| <strong>③ 硬件安全增强</strong> | 对硬件进行<strong>标识</strong>；把硬件级部件（<strong>安全芯片或安全固件</strong>）作为<strong>系统信任根</strong> |
| <strong>④ 运维管控</strong> | 对外部存储器等<strong>硬件连接设备</strong>的使用进行管控；部署<strong>运维管控系统</strong> |

FASR = <strong>固件攻击面减少</strong>；"系统信任根"由<strong>安全芯片/安全固件</strong>提供。"漏洞修复"与"补丁管理"是两件事：前者是<strong>修漏洞</strong>（动作），后者是<strong>管补丁的全流程</strong>（检测→下载→测试→批准→安装）。

## 4 控制安全防护技术（6.4）

分<strong>控制协议安全</strong>与<strong>控制软件安全</strong>两侧（对应安全框架图 C6·P13 的两列）。

### 4.1 控制协议安全防护（五项）

| 技术 | 内容 |
| --- | --- |
| <strong>① 身份认证</strong> | 主要通过<strong>知识类认证、资产类认证、本征类认证</strong>的组合方式实现，确保控制系统执行的控制命令<strong>来自合法用户</strong> |
| <strong>② 白名单技术</strong> | 通过建立<strong>工业控制协议白名单访问控制策略</strong>，过滤一切非法访问，保证只有<strong>白名单内的可信任指令和消息</strong>才能在网络上传输 |
| <strong>③ 访问控制</strong> | <strong>鉴别访问主体的合法身份</strong>后，通过某种途径<strong>准许或限制</strong>用户对数据信息的访问能力及范围，从而<strong>控制对关键资源的访问</strong> |
| <strong>④ 传输加密</strong> | 三种手段：<strong>在协议栈增加安全层</strong>、<strong>在协议应用数据单元增加安全字段</strong>、<strong>改进通信会话的过程</strong> |
| <strong>⑤ 脆弱性测试</strong>（漏洞评估） | 一种<strong>系统化识别</strong>系统、网络、应用中<strong>安全弱点</strong>的安全检测方法，通过<strong>量化分析潜在威胁</strong>并提出<strong>修复建议</strong>，是<strong>漏洞管理与风险管理的核心环节</strong>。其中 <strong>Fuzzing test（模糊测试）占 80%</strong>；模糊测试分<strong>黑盒、白盒、灰盒</strong>三种类型 |

身份认证三种方式：<strong>知识类、资产类、本征类</strong>（对应"你知道什么 / 你拥有什么 / 你是谁"）。

### 4.2 控制软件安全防护（四项）

| 技术 | 内容 |
| --- | --- |
| <strong>① 软件防篡改</strong> | 以<strong>代码测试、完整性校验、代码加密</strong>等方式，防止攻击者篡改工业控制软件 |
| <strong>② 恶意软件防护</strong> | <strong>恶意代码检测、预防和恢复</strong> |
| <strong>③ 认证授权、漏洞修复和补丁升级</strong> | 传统手段，但要<strong>在线、不中断生产</strong> |
| <strong>④ 安全监测与审计</strong> | 利用特定工业软件操作的<strong>周期性</strong>，测量协议不同阶段执行中的<strong>偏差</strong>；利用控制软件中的<strong>时间序列信息</strong>，基于<strong>无监督学习</strong>的方法进行<strong>异常检测</strong> |

"为什么工业控制软件的安全监测要用无监督学习"——因为工业现场<strong>几乎没有带标签的攻击样本</strong>（不能拿生产线做实验），且正常行为<strong>高度规律、周期性强</strong>，所以适合"学正常、报异常"的<strong>无监督异常检测</strong>。这个回答把"工控场景的特殊性"讲透了。

## 5 网络安全防护技术（6.5）

| 技术 | 内容 |
| --- | --- |
| <strong>① 网络隔离</strong> | <strong>限制网络之间的资源共享</strong>，防止信息泄露。典型场景：<strong>工厂内外网隔离、生产网与办公网隔离、工业控制系统隔离</strong>。包括<strong>物理隔离、协议隔离、应用隔离</strong> |

| <strong>④ 通信和传输保护</strong> | <strong>加密技术、校验机制</strong> |
| <strong>⑤ 入侵检测系统（IDS）</strong> | 通过<strong>网络流量分析</strong>，实现<strong>网络流量监测与告警</strong>。两类方法：<strong>基于规则库</strong>（预先定义模式或与已知恶意序列比对）与<strong>基于异常</strong>（早期用机器学习，当前用<strong>深度学习</strong>，用大规模神经网络参数挖掘训练样本背后的知识） |

## 8 工业区块链技术（6.8）

### 8.1 区块链基础

> 【课件 C6·P61】<strong>区块链（Blockchain）</strong>：是一种由<strong>区块（block）</strong>组成的<strong>链式数据结构</strong>，
> 并且是<strong>去中心化</strong>的、<strong>不可篡改</strong>的<strong>分布式账本</strong>技术。通过链式数据结构记录交易和信息，
> 实现数据<strong>透明和安全</strong>。

| 特性 | 含义 |
| --- | --- |
| <strong>透明性</strong> | 账本公开可查 |
| <strong>不可篡改性</strong> | 哈希链式结构保证 |
| <strong>去中心化</strong> | 无单一中心机构 |
| <strong>可追溯性</strong> | 每笔记录可回溯 |
| <strong>减少交易成本和时间</strong> | 去掉中间对账环节 |

典型应用场景（【课件 C6·P63】）：<strong>金融服务、供应链管理、医疗保健、数字身份认证、投票系统、
智能合约</strong>。

区块链五特性：<strong>透明性、不可篡改性、去中心化、可追溯性、减少交易成本和时间</strong>。"区块链 = 比特币"是错的：比特币是<strong>应用</strong>，区块链是<strong>底层技术</strong>（课件 P61 的图把二者画成"比特币 ⊂ 区块链 ⊂ 分布式数据库"的包含关系）。

### 8.2 工业区块链的特征

"为什么工业互联网需要区块链"——一句话：工业互联网要<strong>跨企业</strong>协作，而跨企业之间<strong>没有共同信任的中心</strong>；区块链用<strong>分布式账本 + 智能合约</strong>在<strong>不依赖第三方</strong>的前提下建立信任，正好补上"多主体协作"这块短板。

### 8.3 四个解决方案（挑战 → 方案，一一对应）

| 挑战 | 基于工业区块链的解决方案 |
| --- | --- |
| <strong>信任构建难</strong> | <strong>工业互联网分布式信任管理</strong> |
| <strong>数据确权流转难</strong> | <strong>工业互联网数据确权流转管理</strong> |
| <strong>数据安全共享难</strong> | <strong>工业互联网数据安全共享管理</strong> |
| <strong>事件审计追溯难</strong> | <strong>工业互联网事件审计追溯管理</strong> |

逐条要点（【课件 C6·P66–76】）：

<strong>（1）分布式信任管理</strong>（解决"多平台、多设备、多用户、多工序协作缺乏统一可信身份认证"）

<strong>（2）数据确权流转管理</strong>（解决"数据来源多、流转权属关系确认难、使用责任不清晰"）

<strong>（3）数据安全共享管理</strong>（解决"原始数据共享意愿低、加密数据计算过程过于透明、难追踪"）

<strong>（4）事件审计追溯管理</strong>（解决"跨组织跨区互通联动后缺乏统一高效的追溯审计手段"）

"工业区块链解决了工业互联网安全的哪些核心难题"（课后题 8）——按"<strong>信任、确权、共享、审计</strong>"四个词答，每个词配一句"用什么技术"：信任用<strong>分布式身份账本</strong>、确权用<strong>资产标签上链</strong>、共享用<strong>密文同态计算</strong>、审计用<strong>事件映射逻辑链 + 智能合约</strong>。

## 本章要点

1. <strong>震网病毒</strong>：首个专门针对工控系统的破坏性蠕虫；目标伊朗核电站离心机；<strong>首个主动攻击

2. <strong>三个思考</strong>：物理隔离≠安全、安全机制薄弱、单一防护极易被突破。

4. <strong>五维变化</strong>：设备机械化→智能化（EOS + 微处理器 + 软件）；控制分层封闭局部→扁平开放全局；

 单向→大量多维双向。
5. <strong>控制安全三分析</strong>：IT 渗透到 OT（OT 不再可信）、OT 协议软件安全机制缺失、信息安全与

8. <strong>网络防护五项</strong>：网络隔离（物理/协议/应用）、边界管控、接入管理、通信传输保护、入侵检测
